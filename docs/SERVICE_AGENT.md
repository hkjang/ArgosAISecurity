# Argos Agent 서비스

`argos-agent`는 Linux 호스트의 파일·프로세스 이벤트를 수집하고 위험 판단,
대응, 증거 저장, 백업과 중앙 보고를 수행한다. 자동 차단은 기본적으로 꺼져 있다.

```bash
argos-agent --config /etc/argos/argos.toml
argos --config /etc/argos/argos.toml status
```

기본 설정 경로는 현재 디렉터리의 `argos.toml`이다. 파일이 없으면 기본값으로 실행하며,
Linux 기본값은 `watch_paths=["/home"]`, DB `/var/lib/argos/argos.db`, 백업
`/var/lib/argos/backup`이다. 배포 시 경로를 명시한다. 센서 기본값은 `notify`이며
fanotify는 명시적으로 선택해야 한다. 설정 변경의 자동 재적용은 제공하지 않으므로
정책 검증 후 에이전트를 재시작한다.

## 처리 순서

1. 설정과 서명 정책을 읽고 센서가 실제로 수집할 수 있는 신호에 맞는 임계치를 검사한다.
2. 파일 센서와 선택적 `/proc` 프로세스 감시를 시작한다.
3. 파일 이벤트의 엔트로피 또는 선택한 다중 위치 표본, 프로세스 맥락, 지정 설정 파일의 의미 차이를 평가한다. 알림과 독립적으로 대응 가능 조건을 검사한다.
4. 허용된 대응을 실행한 후 이벤트를 SQLite에 기록하고 변경 파일을 백업 큐에 넣는다.
5. 탐지와 활성화한 중앙 전송·사건 보존 요청을 같은 이벤트 DB 트랜잭션에 저장한다. 전송과 사건 고정은 각각 별도 작업자가 처리한다.

대응 판단은 알림 중복 억제와 분리되어 있다. DB 기록과 파일 전체 백업보다 앞서
차단 필요성을 평가한다. 백업 작업자는 크기가 제한된 별도 큐에서 실행되고,
정해진 I/O 예산과 파일 크기 제한을 적용한다.

## 센서 상태와 유실

파일 센서의 `SensorHandle::health()`와 프로세스 감시의
`ProcessMonitorHandle::health()`는 다음 상태를 반환한다.

| 필드 | 의미 |
| --- | --- |
| `alive` | 핸들이 유지되고 알려진 리더 종료가 발생하지 않음 |
| `delivered_events` | 에이전트 큐에 넣은 이벤트 수 |
| `dropped_events` | 에이전트 큐가 가득 차서 버린 이벤트 수 |
| `errors` | 수집 또는 파싱 실패 수 |
| `kernel_overflows` | fanotify 큐 넘침 또는 notify 재스캔 요구 횟수 |
| `last_event_ms` | 마지막 이벤트 전달 시도 시각, 관측이 없으면 `None` |

수집기는 `try_send`를 사용한다. 큐가 가득 차면 유실을 계수하고 다음 커널 이벤트를
읽으며, 수신측이 종료되면 중단한다. 커널 큐 넘침에서 실제 잃은 이벤트 개수는 알 수
없으므로 `kernel_overflows`를 `dropped_events`에 임의의 개수로 합산하지 않는다.

`notify`는 내부 OS 수집 스레드의 독립적인 생존 정보를 공개하지 않는다.
따라서 해당 백엔드의 `alive`는 활성 핸들 상태를 뜻하고 모든 내부 장애를 증명하지는
못한다. 이벤트가 없는 시간도 정상일 수 있으므로 마지막 이벤트 시각만으로 장애를
판정하지 않는다. 오류 및 유실 계수는 에이전트 재시작 전까지 누적된다.

fanotify 리더가 FD를 소유하고, 핸들 해제는 중단 플래그를 설정한다. 비차단 FD와
짧은 `poll` 대기로 중단을 확인하여 다른 스레드에서 FD를 닫고 재사용하는 경쟁을 피한다.
파일 FD는 이벤트 전달 실패나 큐 포화 여부와 무관하게 닫는다. 경로 필터는 디렉터리
구성요소 단위로 비교하여 `/data/watch`와 `/data/watched`를 구분한다.

## 프로세스 신원과 승인 작업 맥락

프로세스 이벤트는 PID 외에 `/proc/<pid>/stat`의 시작 ticks와 `boot_id`, 실행 파일 경로를
저장한다. 이전 데이터에서 없는 값은 `None`으로 남겨서 모르는 신원을 추측하지 않는다.
`uid`는 `/proc/<pid>/status`의 유효 UID이며 실제 실행 권한을 나타낸다.

프로세스 감시는 기본 활성화이며 `process_monitor.interval_ms`는 기본 1,000ms
(실제 최소 100ms)다. 첫 스캔은 메모리의 비교 기준이며 모든 기존 프로세스를 DB에
등록하지는 않는다. 이후 같은 PID라도 시작 ticks·boot_id, 실행 파일·명령행·이름,
네 가지 UID/GID 또는 capability 집합이 달라지면 새 관측 이벤트를 낸다.
`stat`의 이름에는 공백과 괄호가 들어갈 수 있으므로 마지막 닫는 괄호 이후에 있는
고정 필드를 해석한다. 프로세스 정보 수집 전후의 시작 ticks·이름·실행 파일·자격을
대조하고 도중에 바뀌면 해당 스냅샷을 버린다. `credentials.uids`와 `gids`는
real/effective/saved-set/filesystem 순서이며 capability 다섯 집합도 저장한다.
`processes` 표보다 자세한 필드는 `evidence`/MCP JSON에서 확인한다.

fanotify는 수집 직후 확인한 완전한 프로세스 맥락을 파일 이벤트에 첨부한다.
UID·실행 파일·시작 ticks·boot_id 중 하나라도 확인하지 못하면 맥락은 `None`이며,
정상 작업 승인 예외의 근거로 사용하지 않는다. `process.ancestors`는 확인 가능한 부모부터 최대 4단계의 인스턴스 신원이다. PID를 제공하지 않는 notify는 프로세스 맥락이 `None`이다.

`/proc` 폴링은 커널 exec 추적이 아니다. 폴링 사이에 시작·종료한 단명 프로세스와
같은 실행 파일·같은 인자로 수행한 재실행을 놓칠 수 있다. 파일 이벤트와 이후 `/proc`
조회는 원자적 스냅샷이 아니므로 실행 전환을 완벽하게 재구성하는 것은 향후 eBPF
기반 수집의 범위다.

## 백업·복구와 중앙 보고

시작 시 베이스라인과 변경 후 백업은 모두 미검토 상태로 보관한다. 시작 시점이라는
이유만으로 정상본으로 인정하지 않는다. 정상 복구 지점 지정, 미리보기, 복구 시험,
보존 정책은 [안전한 복구 지점](FEATURE_RECOVERY.md)에 설명되어 있다.

중앙 보고는 별도 작업자에서 HTTP를 호출한다. 탐지와 전송 대기 데이터는 SQLite에
함께 저장되며, 통신 실패 시 재시도한다. 중앙 수신측은 이벤트 식별자로 중복을 제거한다.
에이전트는 30초마다 `<db_path>`의 확장자를 바꾼 `health.json` 파일에 센서·큐·백업·
보존·분석·정책 상태를 기록한다. 예를 들어 `argos.db`이면 `argos.health.json`이다.
중앙 생존 신호에는 합산한 보호 정상 여부와 전송 대기·실패 건수를 보낸다. 모든 상세
로컬 지표를 중앙에 전송하는 것은 아니다. 센서 오류가 없는 경우와 센서 자체가 중단된 경우를 구분한다.

## 검증 범위

`cargo test -p argos-sensor`는 큐 포화 유실, 수신측 종료 시 중단, 리더 종료 상태,
notify 재스캔 알림, fanotify 메타데이터 경계 및 넘침 처리, 경로 범위, `/proc` 파서,
PID 재사용·실행 변경과 유효 UID를 검증한다. fanotify 관련 테스트는 생성한 메타데이터와
Unix 소켓을 사용하여 root 권한이나 실호스트 fanotify 마크 없이 수행한다.


## 확장 분석과 정책 유효기간

다중 시간 구간과 분산 집계는 `[detection.multi_window]`, 앞·중간·끝 표본은 `[detection.content_sampling]`에서 명시적으로 활성화한다. 집계 경보는 임의 PID의 자동 종료 근거로 사용하지 않는다. 당시 표본·수집 시각·프로세스 자격·제한된 계보는 증거 JSON에 보관한다. 파일 수집이 지연되면 표본은 더 늦은 파일 내용을 반영할 수 있다.

`[semantic].files`에 지정한 Linux 설정 파일은 [의미 변화 감시](FEATURE_LINUX_ANALYSIS.md)로 별도 분석한다. 점수가 있는 탐지의 보존 요청을 DB에 기록하고 별도 작업자가 관련 정상 복구 지점을
`detection-<탐지 ID>` 사건으로 고정한다. 요청은 최대 10,000건이며 재시작 후에도
1~60초 간격으로 재시도한다. `backup.pin_pending`·`pin_failed`·`pin_overflow`·
`pin_completed`·`pin_worker_errors`와 실제 `retention list` 결과를 함께 확인한다.
백업이 비활성화되면 자동 보존 요청도 생성하지 않는다. [비동기 보존](FEATURE_RELIABILITY.md#사건-보존-대기열)에 완료·누락 조건을 설명한다.

서명 정책이 설정되면 활성화 실패 시 시작을 중단한다. 실행 중 서명 유효기간을 벗어나면 자동 차단을 중단하고 수락한 탐지 설정을 유지한다. 이 상태는 시계가 돌아와도 자동 해제하지 않으며 기간·서명 검증을 통과하는 정책으로 재시작해야 한다. 이미 만료된 정책이라면 유효기간을 갱신한 더 높은 버전을 서명해 배포한다. 로컬 보호 상태에는 정책 버전·해시·기간·invalid 상태를 기록한다. 자세한 조건은 [정책 신뢰](FEATURE_POLICY.md)를 따른다.
