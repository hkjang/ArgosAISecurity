# Argos AI Security 개발 요건서

기준: **v0.4.0, 2026-09-27**. 1~19장은 제품 목표와 장기 요구를 포함한다. 항목이 있다는 이유만으로 해당 릴리즈에서 구현·검증되었다고 해석하지 않는다. 현재 구조는 [아키텍처](ARCHITECTURE.md), 기능별 진행 상태는 [로드맵](ROADMAP.md), 실행한 시험과 미검증 범위는 [검증 기록](PLATFORM_VALIDATION.md)을 함께 확인한다.

## 현재 구현 상태

‘구현’은 아래에 적은 범위의 코드와 검증 경로가 있다는 뜻이며 운영 성능·탐지율을 보증하지 않는다. ‘부분 구현’은 원래 요구 전체를 충족하지 않은 상태다.

| --- | --- | --- |

| 행위 탐지 | 구현 범위 한정 | 센서별 점수·규칙별 승인 작업·미끼 파일, 선택적 다중 시간창·부분 내용 표본. 전체 암호화 탐지나 운영 탐지율 검증은 아님 |

## 6. AI Copilot 질문 예시

아래는 목표 질문이다. 현재 `ask`는 설정한 단일 로컬 DB의 지원 기간·PID 조회를 사용하며 다른 서버·네트워크 이벤트로 자동 확장하지 않는다. ‘복구해도 안전하다’는 AI 답변을 정상본 판정이나 복구 승인으로 사용하지 않는다. 범위·누락과 근거 ID를 먼저 확인한다.

| 사용자 질문                 | 기대 응답                       |
| ---------------------- | --------------------------- |
| 지난 24시간 동안 가장 위험한 서버는? | 위험도 순위와 근거 제공               |
| 이 프로세스가 왜 차단됐어?        | 파일 변경 패턴, 권한, 네트워크 행위 기반 설명 |
| 랜섬웨어 가능성이 높은 이벤트만 보여줘  | 고위험 이벤트 필터링                 |
| 이 서버를 복구해도 안전해?        | 복구 가능성, 잔존 위험, 권장 조치 제공     |
| 오탐 가능성 있어?             | 정상 배치 작업 여부, 과거 패턴 비교 결과 제공 |

## 8. 탐지 엔진 요건

이 표의 지연은 목표다. 현재 기본 탐지는 규칙 기반이며 AI 위험 점수를 자동 차단 판단에 사용하지 않는다. 다중 시간창과 내용 표본의 구현 경계는 21장에 정의한다.

| 항목       | 요건                                                |
| -------- | ------------------------------------------------- |
| 탐지 방식    | 행위 기반 탐지 우선                                       |
| 룰 구조     | 정적 룰, 동적 룰, 점수 기반 룰, AI 보조 판단                     |
| 위험 점수 요소 | 파일 변경 속도, 변경 파일 수, 엔트로피, 프로세스 신뢰도, 사용자 권한, 자산 중요도 |
| 오탐 방지    | 백업, 로그 로테이션, DB dump, CI/CD 배포, 대용량 배치 작업 예외 처리   |
| 탐지 지연    | 주요 이벤트 발생 후 1초 이내 1차 판단                           |
| AI 분석 지연 | 사고 요약 및 원인 분석 10초 이내 목표                           |

## 12. 성능 요건

기능 존재 여부와 함께 차단·복구 결과를 증거로 확인한다.

| 영역 | 보완 요구 | 검증 기준 |

| 탐지/대응 | 센서별 도달 가능한 점수, 알림 억제와 대응 분리, PID 재사용 방지 | 80점 통과 시 알림이 없어도 판단; pidfd와 시작 신원이 일치하는 테스트 자식만 종료 |
| 복구 | 정상 판정과 해시 무결성 분리, 공격 이전 추천, 별도 경로 미리보기 | 손상된 최신본을 자동 선택하지 않고 검토한 정상 내용 복구 |
| 정책 | 저장 이벤트 재생 비교와 기간/누락/신원 한계 | 기존/후보 알림·차단 예상 대상·근거 ID 비교; 정책/DB 변경 없음 |
| 운영 | 제한 큐, 백업 I/O 처리 예산, 센서 생존/유실 지표, 영속 전송 큐 | 서버 단절/ACK 유실 후 재시도와 중복 제거; 조용한 호스트도 생존 신호 |
| 인증/격리 | 운영 인증 필수, 개별 에이전트 인증, IPv4/IPv6 관리 경로 제한 | 다른 에이전트 사칭 거부; 기존 의심 연결·전달 트래픽 실제 패킷 차단 |
| 정상 작업 | 승인 기간·경로·실행 파일·계정 모두 일치할 때 한정 조정 | 정상 배포 시나리오 오탐 감소, 범위 밖 공격 탐지 유지 |

ITSM 자동 연동, Suricata/Zeek 연결 상관분석, eBPF/mTLS/Kubernetes는 별도 후속 통합이다. 현재 승인 작업은 서명 가능한 정책 데이터로 입력한다. 실제 분석가의 조사 시간 단축과 운영 성능 목표(12장)는 현장 측정이 필요하다.
