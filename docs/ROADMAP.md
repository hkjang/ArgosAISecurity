# 검증 가능한 Linux 보안 플랫폼 후속 계획

기준: v0.5.0, 2026-09-27 문서 점검. 현재 구현과 후속 제안을 구분하며, 아래의 후속 항목은 구현 완료를 의미하지 않는다. 기존 실행 결과와 환경별 미검증 범위는 [플랫폼 검증 기록](PLATFORM_VALIDATION.md)을 따른다.

## 1순위: 정책 수명주기와 보존 안전성

### 정책 재적용 방지와 승인된 롤백

구현 완료: 서명 대상의 정책 ID·증가 버전·발급/시작/만료 시각·호스트/그룹·키 ID를 로컬 신뢰 설정과 대조한다. 정책 원문·실효 설정·최대 버전·감사 기록을 SQLite 트랜잭션으로 저장하고 동시 적용을 직렬화한다. 동일 버전·동일 해시의 유효한 재시작만 허용하며, 변경된 동일 버전이나 하위 버전을 거부한다.

롤백도 새 높은 버전으로 서명하며 이전 수락 정책의 버전·해시·동일 설정과 새 승인 ID·사유를 요구한다. 신뢰 키는 로컬 운영 설정만 변경할 수 있다. 잘못된 정책이나 상태 저장 실패는 시작을 중단하고 기본 설정으로 전환하지 않는다. 실행 중 기간 이탈은 자동 차단을 끄고 수락한 탐지 설정을 유지하며 보호 저하를 표시한다.

확인된 범위는 [정책 검증](FEATURE_POLICY.md#검증)의 키/기간/대상·재시작·동시 적용·승인 재사용·감사 실패 회귀 시험이다. 현재 승인 ID는 서명권자의 승인을 나타내며 외부 ITSM이나 다중 승인자를 확인하지 않는다. 파일 권한은 로컬 관리자/root의 상태 삭제·전체 스냅샷 롤백을 막지 못한다. 중앙 배포·신뢰 시계·전원 차단 환경 시험과 실행 중 정책 교체는 남은 범위다.

### 사건별 보존 고정

구현 완료: `known_good`와 독립된 사건 참조로 미검토 버전도 증거 보존하며, 동일 버전에
여러 사건이 연결될 수 있다. 점수가 있는 탐지에 대해 경로별 탐지 이전 정상본을
고정하는 `detection-<ID>` 사건 요청을 탐지와 같은 트랜잭션에 기록하고 별도 작업자가 처리한다.
미완료 요청은 재시작 후 재시도하며 상한 초과는 누락으로 계수한다. 고정 완료는 실제
참조로 확인한다. 수동 CLI는 명시한 경로·버전을 고정한다.
보존과 정리는 직렬화된 트랜잭션으로 처리한다. 정상 판정 취소 후에도 활성 사건
참조가 유지되며, 고정만으로 원본 복구를 허용하지 않는다.

해제에는 최초 요청자와 다른 승인자 문자열·새 승인 ID·사유가 필요하고 일괄 해제는
원자적으로 처리한다. 참조·승인·감사 이력은 버전 정리 후에도 남는다. 재시작·다중
사건·동시 고정/정리·`prune(0)`·승인 재사용 거부는 단위 시험으로, 자동 고정·CLI
해제·미검토 복구 거부는 [시나리오 도구](../scripts/security-scenarios.py)로 검증한다.

남은 범위는 승인자의 실제 외부 신원과 권한 검증, 감사 보관 용량 정책 및 로컬
관리자/root의 저장소 삭제·전체 스냅샷 롤백에 대한 외부 보존이다. 현재 승인 정보는
로컬 CLI와 OS 파일 권한을 신뢰하며 원격 RBAC나 두 사람의 인증을 의미하지 않는다.

## 2순위: Linux 행위와 파일 변화 탐지

### 여러 시간창과 프로세스 계보·계정·경로 상관분석

짧은 급증과 장시간 저속 변경을 별도 시간창으로 평가한다. PID 인스턴스별 증거와 계보·유효 계정·보호 경로별 집계를 구분하여, 자식 프로세스나 여러 PID에 분산된 변경을 탐지한다. 승인 작업이 적용된 이벤트와 다른 계보의 이벤트를 혼합해 예외를 넓히지 않는다. 호스트 집계만으로 특정 PID를 종료하지 않고 실제 대응 대상의 기여 근거를 남긴다.

제한된 기반 구현 완료: 설정으로 켜는 다중 시간창, 최대 4단계의 관측된 부모 신원, 규칙별 예외, 누락 시 차단 근거 제한을 합성 재생으로 검증했다. 실제 운영 데이터셋에서 오탐·누락·성능을 측정하고 재부모화와 센서 수집 경합을 검증하는 단계는 남아 있다.

추가 검증·확대 기준:

- 단일 PID 급증, 긴 간격의 저속 변경, 자식 여러 개의 분산 변경을 탐지하고 근거 계보·시간창을 출력한다.
- PID 재사용·재부팅·부모 종료 후 재부모화에서 서로 다른 인스턴스의 점수가 섞이지 않는다.
- 정상 배포·백업·DB 덤프와 공격을 동일 데이터셋에서 비교해 오탐 및 누락을 수치로 기록한다.

### 부분 암호화와 정상 엔트로피 기준

읽기 예산 안에서 앞·중간·끝 또는 센서가 제공하는 변경 구간을 표본화한다. 샘플 위치·바이트 수·오류·누락을 근거와 함께 저장한다. 명시적으로 검토한 기준값과 비교하되, 현재 의심 파일을 자동으로 정상 기준에 편입하지 않는다. 압축·암호화 데이터·DB 파일처럼 원래 엔트로피가 높은 형식은 유형과 작업 맥락을 함께 사용한다.

제한된 기반 구현 완료: 앞·중간·끝 고정 총 예산, 유형 힌트, 크기·위치가 같은 이전 관찰 대비 변화, 제한된 이력과 저장 증거 재생을 제공한다. 중간·끝 변경과 변경 없는 ZIP 표본, 실제 읽기 바이트 상한을 시험했다. 이전 관찰은 미검토 데이터이며 승인된 정상 기준이 아니다. 변경 구간 센서와 실제 DB/압축 워크로드 평가, 검토된 정상 기준 연계는 남은 범위다.

추가 검증·확대 기준:

- 머리 부분을 유지하고 중간이나 끝만 바꾼 시나리오, 크기가 큰 파일의 일부 변경에서 기존 앞부분 샘플 대비 탐지 변화와 읽기 비용을 측정한다.
- 압축 파일 재생성·정상 암호화·DB 덤프를 공격으로 단정하지 않으며, 기준값이 없는 경우 이를 누락으로 표시한다.
- 파일이 샘플링 중 바뀌거나 읽기에 실패하면 완전한 비교 결과로 표시하지 않는다. 정책 재생은 저장된 당시 샘플만 사용한다.

### Linux 설정의 의미 변화

제한된 기반 구현 완료: 명시된 authorized_keys·sudoers·cron·systemd 파일의 의미/순서/소유권/권한 차이를 기록한다. 시작 시 미수집과 파싱 실패도 보호 상태에 표시한다. 전체 유효 설정 평가·include 자동 추적·서비스 적용 확인은 남아 있다. [구현 범위](FEATURE_LINUX_ANALYSIS.md)를 참고한다.

후속 확장은 SSH·sudoers·cron·systemd 서비스·계정 및 인증 설정을 대상으로 내용·권한·소유권 변화에서 보안 의미를 추출한다. 파일별 구문을 이해하는 규칙과 검증 명령을 사용하고, 비밀값은 표시·전송 범위를 제한한다. 일반 대량 변경 점수와 별도의 근거를 제시한다.

추가 검증·확대 기준:

- 주석·공백만 바뀐 경우와 원격 로그인 허용, 권한 상승 허용, 새 지속 실행 작업처럼 의미가 달라진 경우를 구분한다.
- include 파일·심볼릭 링크·원자적 파일 교체·권한 변경을 시험하고, 파싱 실패를 정상 판정으로 처리하지 않는다.
- 정상 패키지 업데이트·승인된 설정 배포에서도 예외 범위를 벗어난 의미 변경이 근거로 남는다.

### 프로세스 자격과 실행 파일 신뢰

자격 기록 구현 완료: 실제·유효·저장·파일시스템 UID/GID와 capability 집합을 수집하고 변화 시 새 이벤트를 저장한다. 실행 파일 해시·소유권·패키지 소속과 서비스 매핑은 후속 범위다.

실 UID·유효 UID·저장 UID·파일시스템 UID와 GID, capability 집합의 변화를 명시적 필드로 기록한다. 후속 확장은 실행 이미지의 해시·inode·장치·패키지 소속·서명 또는 검토한 기준을 연결한다. 경로 일치와 실행 파일 신뢰를 구분하고, 삭제된 실행 파일·파일 없는 실행·실행 중 이미지 교체를 표현한다. `/proc` 폴링의 관측 한계를 유지하며 eBPF 등 추가 센서가 제공한 정보와 출처를 구분한다.

추가 검증·확대 기준:

- 같은 PID의 exec, setuid 전환, capability 획득·해제, 경로는 같지만 내용이 교체된 실행 파일을 구별한다.
- 수집 경합·접근 거부·센서 미지원은 알 수 없음으로 남기며 신뢰나 정상 UID를 추정해서 채우지 않는다.
- 오래된 데이터 마이그레이션에서 새 자격 필드는 미수집 상태를 유지하고, 승인 작업은 필요한 맥락이 없으면 예외를 적용하지 않는다.

## 3순위: 조사 결과·서비스 영향·과부하 운영

### 증거 패키지와 서비스 영향

증거 패키지 기반 구현 완료: 원본 ID가 있는 사건 근거·대응 이력·내보내기 시점 마지막 수락 정책, 마스킹, 파일별 SHA-256과 검증 명령. 서비스 영향·복구 지점 원본·발급자 인증 및 사건 시점 정책 증명은 후속 범위다.

후속 확장은 선택한 사건의 원본 이벤트, 프로세스 인스턴스·계보, 사건 시점의 적용 정책과 버전, 대응 결과, 복구 지점 참조를 함께 내보내는 것을 목표로 한다. 조회 범위·누락·시간 기준·수집 출처를 명시하고 파일별 해시와 검증 가능한 manifest를 제공한다. AI 해석과 원본 증거를 구분한다. 대응 전후 서비스 연결·상태 점검과 관리자 피드백을 별도 기록하여 공격 차단 성공과 업무 정상 여부를 함께 평가한다.

추가 검증·확대 기준:

- 오프라인 검증에서 패키지 변조·누락을 식별하고, 원본 근거 ID를 조회 결과에 대응시킨다.
- 비밀값·개인정보의 제외 범위와 제외 사실을 남기며, 조회 상한에 걸린 패키지를 완전한 사건 기록으로 표시하지 않는다.
- 테스트 서비스의 차단 전후 가용성·오류율·복구 시간을 수집하고, 영향 평가 자체가 실패하면 성공으로 기록하지 않는다.

### 자원 한도와 단계별 축소 동작

CPU·메모리·파일 읽기·디스크 사용량의 예산 및 센서별 우선순위를 정의한다. 초과 시 샘플링·백업·부가 분석의 축소 단계를 명시하고 전환·해제·누락량을 기록한다. 핵심 대응 판단에 필요한 증거가 부족하면 그 한계가 정책 판단과 운영 화면에 전달되어야 한다. outbox 디스크 상한 및 장기 단절 시 동작은 데이터 보존 요구와 함께 정한다.

추가 검증·확대 기준:

- 대량 이벤트·큐 포화·장기 중앙 단절·디스크 부족·느린 백업 저장소를 주입해 단계별 동작과 지표를 확인한다.
- 설정 예산 초과 시 지연·유실·메모리 증가를 측정하고, 과부하 해소 뒤 정상 단계로 복귀한다.
- 센서 고장, 전송 불가, 분석 축소, 실제 위협 없음이 상태 화면에서 서로 구별된다.

## 시나리오 시험과 배포 판단

각 단계는 기존 [재현 명령](PLATFORM_VALIDATION.md#재현)을 유지하고 필요한 시나리오만 추가한다. 신규 로직은 합성 이벤트 재생으로 경계 조건을 확인한 뒤 격리된 Linux 시험 환경에서 센서부터 대응·복구·감사까지 검증한다.

| 시나리오 | 확인할 결과 |
| --- | --- |
| 정상 배포·백업·DB 덤프·패키지 업데이트 | 승인 범위, 오탐 수, 처리 비용, 서비스 영향 |
| 고속·저속·다중 프로세스·부분 암호화 | 탐지 지연, 누락, 대응 대상 근거, 실제 종료 확인 |
| 프로세스 exec·PID 재사용·권한 전환 | 인스턴스·실행 이미지·자격 변화 분리와 오차단 방지 |
| 구정책 재전송·만료·다른 대상·키 폐기·롤백 | 거부 또는 명시적으로 승인된 적용, 재시작 후 기록 보존 |
| 정상본·사건 고정·용량 제한·객체 손상 | 보존 참조 유지, 안전한 실패, 원본 유지 미리보기, 복구 검증 |
| 센서 중단·통신 단절·ACK 유실·자원 고갈 | 보호 상태 구분, 중복 없는 재전송, 축소 상태와 누락량 |

운영 처리량·CPU/I/O 목표와 조사 시간 단축은 실제 대상 환경에서 별도로 측정한다. 관찰 모드의 정책 재생 결과와 서비스 영향 기준을 충족한 뒤 운영자가 정한 소수 서버에서 검증하고 확대한다. 이 계획만으로 해당 성능이나 탐지율이 달성되었다고 주장하지 않는다.

## v0.3.0에서 추가한 운영 검증

[보호 공백 검사](FEATURE_COVERAGE.md), [SQLite/PostgreSQL 복구 시험](FEATURE_SERVICE_RECOVERY.md), [별도 서버 보관·서명 수신증명](FEATURE_REMOTE_VAULT.md), [정책 예외 감사](FEATURE_EXCEPTION_AUDIT.md), [AI 인용 검사](FEATURE_AI_VALIDATION.md)를 구현했다. 앞의 남은 범위 중 외부 보존과 DB 복구는 이 범위까지 진척되었으며, 원격 관리자 삭제 방지/WORM·자동 보관·전체 서비스 RTO/RPO는 계속 후속이다.

다음 검증은 실제 업무 백업과 정책 예외를 이용한 관찰 모드 시험, 보호 경로의 파일시스템·컨테이너별 공백 확인, 사내 모델의 구조화 응답 준수율과 분석 품질 측정이다. 합성 시나리오 성공을 운영 탐지율이나 복구 완료 보장으로 바꾸지 않는다.

## v0.4.0에서 추가한 지속성 검사

[영속 보관 큐](FEATURE_VAULT_QUEUE.md), [보관 용량 보호](FEATURE_VAULT_CAPACITY.md), [복구 보고서 v2 재검증](FEATURE_SERVICE_RECOVERY.md)을 구현했다. 통신 복구 후 명시적인 drain 재실행, 용량 초과 뒤 기존 자료 접근, 계획·백업 변경 후 과거 보고서 거부를 실제 CLI 시나리오로 확인한다. 자동 예약 업로드와 전체 서비스 복구는 계속 후속이다.

다음 개선 후보는 우선순위대로 아래와 같다. 현재 구현을 의미하지 않는다.

1. **예약 전송·상태 통합:** systemd timer 또는 전용 작업자, 재시도 지연/미전송 나이/용량 차단을 중앙 생존 상태에 포함. 장기 단절과 재시작 후 중복 없는 전달을 시험한다.
2. **복구 시험 출처 인증:** 보고서 서명키·신뢰 목록·키 ID·만료/폐기를 정의하고, 무서명 일관성 검사와 별도로 신뢰 출처 및 외부 시각을 확인한다.
3. **용량 압박 운영 절차:** 관리자에게 읽기 전용 정합성 진단·필요 공간·이력 보관 계획을 보여주고, 복구 자료를 삭제하지 않는 이전 도구를 제공한다.

## v0.5.0 큐 운영과 다음 단계

활성 큐·완료 수신증명 분리, 항목 임대, 오류 분류, JSONL 내보내기·검증, systemd 예약 전송을 구현한다. 중앙 생존 상태와의 통합은 후속이다. v0.6.0은 분할 보관·완료 묶음·원격 목록·현재 관리자 판정/취소, 원본 서버와 로컬 DB 없이 64MiB 초과 백업의 새 경로 복원/시험으로 범위를 잡는다.

이후에는 사건 당시 정책/실효 설정/근거 ID를 고정하는 판단 원장, 네 실행 파일의 내장 소스 커밋과 서명 빌드 기록, AI 수치 사실의 원본 대조, 시험 실행자 서명과 실행 ID/계획·백업 해시 결합을 검토한다. 보관 서버 서명과 시험 실행자 인증은 별도 신뢰 경계다.
