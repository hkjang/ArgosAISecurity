# 사고 증거 패키지

```bash
argos evidence-export 42 --out /secure/export/incident-42 --window-secs 300 --limit 1000
argos evidence-verify /secure/export/incident-42
```

운영 서비스와 같은 `--config`를 지정하고 `threats`에서 확인한 로컬 탐지 ID를 사용한다. `--out`의 부모 디렉터리는 미리 존재해야 한다.

지정 탐지를 중심으로 로컬 이벤트·프로세스·탐지·대응 결과와 정책 상태를 새 디렉터리에 저장한다. 기존 디렉터리는 덮어쓰지 않는다. Linux에서는 디렉터리 0700, 파일 0600으로 생성한다.

| 파일 | 내용 |
| --- | --- |
| `evidence.json` | 탐지 ID, 기간별 근거와 원본 ID, 종류별 전체 건수·조회 누락, 대응 이력 |
| `policy.json` | 내보내는 시점에 저장된 마지막 수락 정책 및 감사 상태, 또는 서명 없는 로컬 설정임을 명시한 스냅샷 |
| `manifest.json` | 형식 버전, 수집 시각, 파일 크기와 SHA-256, 마스킹 여부와 범위 |

기본값은 경로·실행 파일·명령행·탐지 요약·자유 서술 사유·정책 식별 문자열을 제거한다. 시간, 근거 ID, PID, UID와 수치·조회 누락은 유지한다. 원문이 필요한 권한 있는 담당자는 `--include-sensitive`로 명시한다. 이 옵션은 개인정보를 자동 탐지하는 기능이 아니며 포함 범위를 검토해야 한다.

검증 명령은 누락·추가 파일, 파일 크기·해시 불일치와 심볼릭 링크를 거부한다. 해시는 파일과 manifest 사이의 일치 여부를 검증한다. 발급자 서명이나 원본 진위 증명이 아니므로 manifest는 신뢰할 수 있는 경로로 전달·보관한다.

조회 상한은 패키지에서도 유지한다. 일부 근거가 잘리면 전체 사건 기록으로 표시하지 않는다. 이벤트·대응·정책은 각각 읽기 스냅샷이므로 전체를 하나의 원자적 시점에 촬영한 디스크 이미지가 아니다. 저장된 정책은 마지막 수락 설정이며 사건 시각에 해당 프로세스가 실제로 그 정책으로 실행 중이었다는 증명은 아니다. 백업 원본 파일, 실행 파일 본문, 네트워크 패킷은 이번 패키지에 포함하지 않는다.


시간 범위는 지정 탐지의 앞뒤 각각 `--window-secs`(기본 300초)이며 `--limit`는
종류별 1~10,000건(기본 1,000건)이다. 파일별 크기는 64 MiB로 제한한다. 내보내기
실패 시 일부 파일만 있는 디렉터리가 남을 수 있으므로 완료·검증 결과를 확인하고
다시 만들 때는 새 출력 경로를 사용한다. 자동 복구나 사건 보존 해제를 실행하지 않는다.

## v0.3.0 추가 확인

패키지를 별도 서버에 보관하고 고정 공개키로 수신증명을 확인하려면 [원격 보관](FEATURE_REMOTE_VAULT.md)의 `vault upload-evidence`를 사용한다. 이는 발급자 또는 사건 당시 정책의 진실성을 인증하는 서명은 아니다.

v0.4.0의 [영속 대기열](FEATURE_VAULT_QUEUE.md)에서 검증한 패키지 바이트를 보존해 재전송할 수 있다. 세 파일은 각각 등록·전송되므로 모든 항목의 완료와 manifest 검증을 확인한다. 대기열 경로는 패키지 자신이나 내부 경로로 지정할 수 없다.
