# 보호 경로 공백 검사와 전달 시험

에이전트가 살아 있어도 설정된 디렉터리가 교체되거나 새 마운트가 생기면 의도한 범위의 감시가 끊길 수 있다. 보호 공백 검사는 센서 등록 성공 직후 기록한 기준과 현재 경로를 비교하고, 읽지 못한 범위를 보호 상태에 표시한다. 경로 인벤토리와 실제 이벤트 전달 시험은 서로 다른 확인이다.

```toml
[coverage]
enabled = true
interval_secs = 30
max_entries = 10000
```

기본값은 활성화, 검사 완료 후 다음 검사까지 30초 대기, 검사 한 번에 전체 보호 경로 합계 10,000개 항목이다. 간격은 1~3,600초, 항목 상한은 1~50,000개, 보호 루트는 1~128개다. 루트 자신도 항목에 포함한다. 순회는 이벤트 처리와 별도의 작업자에서 실행하며 파일 내용을 읽거나 경로를 변경하지 않는다.

## 읽기 전용 상태 확인

```bash
argos coverage status
```

에이전트의 최근 건강 상태에서 검사 결과·시각·나이·작업자 생존 여부를 확인한다. 주요 판정은 다음과 같다.

| 표시 | 의미 |
|---|---|
| `no_observed_gap` | 이번 검사 범위에서 관측한 공백이 없음. 전체 감시의 성공 증명은 아님 |
| `gap_or_incomplete` | 루트/마운트 변경, 접근 실패, 제외 경로 또는 검사 상한 등 공백·미확인 범위가 있음 |
| `pending_or_unavailable` | 첫 검사가 완료되지 않았거나 결과를 얻지 못함 |
| `stale: true` | 검사 시작으로부터 `max(60초, 검사 간격 × 2)`를 넘었거나 시계가 역전됨 |
| `worker_alive: false` | 검사 작업자가 종료됨 |

공백, 미완료, 오래된 결과, 종료된 작업자는 에이전트의 정상 보호 상태로 표시하지 않는다. 명령은 건강 상태 파일 자체가 60초보다 오래되어도 오류를 반환한다. 검사를 꺼 둔 상태는 `not_checked`이며 감시가 검증되었다는 뜻이 아니다.

다음 항목을 확인한다.

- 구성한 경로의 정규화 대상, 등록된 루트의 장치·inode가 바뀌거나 사라졌는지
- 현재 검사 스레드의 마운트 네임스페이스와 보호 범위의 마운트 ID·옵션·구성이 바뀌었는지
- fanotify에서 보호 루트의 마운트로 등록되지 않은 하위 마운트가 있는지
- 현재 에이전트 권한으로 경로를 조회·읽기·탐색할 수 있는지
- 심볼릭 링크 제외, 비정규 파일, UTF-8로 표현할 수 없는 경로, 항목·깊이·시간 예산 초과가 있는지

심볼릭 링크 대상은 재귀 탐색하지 않고 공백으로 표시한다. Linux에서는 열린 디렉터리 FD를 기준으로 하위를 열며 마지막 경로 성분의 링크를 따라가지 않는다. 깊이는 64단계, 순회 예산은 5초다. 루트별 문제 목록은 최대 32개이며 추가 문제 수는 `omitted_issues`로 남긴다. 동일 마운트 지점의 중첩으로 범위를 결정할 수 없으면 관련 보호 경로에만 모호함을 표시한다. 무관한 경로의 마운트 변경은 해당 루트의 변경으로 취급하지 않는다.

## 지정 경로의 이벤트 전달 시험

실행 중인 에이전트와 같은 설정·이벤트 DB를 사용해 다음을 실행한다. `--out`은 존재하지 않는 새 파일이어야 한다.

```bash
mkdir -m 700 /srv/protected/test
argos coverage probe --directory /srv/protected/test --timeout-secs 10 --out ./coverage-probe.json
```

예시의 `/srv/protected`는 설정에 등록된 감시 경로이고, 명령 실행 계정이 하위 디렉터리를 만들 수 있어야 한다. 이미 존재하는 시험 디렉터리는 `mkdir` 단계를 생략한다. 시험 디렉터리는 설정된 감시 경로 안에 미리 존재해야 한다. Linux에서는 실행 계정 소유이며 그룹·다른 계정에 쓰기 권한이 없어야 한다. 명령은 고유한 이름의 작은 시험 파일을 권한 `0600`으로 생성하고, 해당 경로의 새 이벤트 ID가 로컬 DB에 도착하는지 확인한다. 기본 대기 시간은 10초이고 1~60초로 지정할 수 있다. 내용을 그대로 유지한 시험 파일만 정리를 시도하며 정리 성공 여부를 결과에 남긴다.

이 명령은 파일을 실제로 쓴다. 시험 이벤트도 일반 탐지 규칙을 거치며 탐지·차단·백업 예외로 만들지 않는다. 결과의 `success`, `event_id`, `writer_succeeded`, `directory_unchanged`, `content_unchanged`, `cleaned_up`을 함께 확인한다. 한 파일의 성공은 전체 디렉터리, 다른 호스트·컨테이너, 자동 차단, 백업·복구의 성공을 뜻하지 않는다.

## 확인할 수 없는 범위

등록 직후 기준은 센서가 전달받은 정규 경로와 비교하지만 커널 watch의 실제 inode 목록을 읽은 결과는 아니다. 센서 등록과 기준 수집 사이의 교체, 검사 중 이동 후 원상복귀하는 경합, 검사 사이의 짧은 마운트 변경을 모두 배제하지 못한다. 인벤토리는 원자적 파일시스템 스냅샷이 아니다. 자동 재등록·수리도 하지 않는다.

5초는 순회 사이에 확인하는 작업 예산이다. 네트워크 파일시스템에서 단일 커널 I/O가 멈추면 강제 중단할 수 없으므로 결과 나이와 `stale`을 확인해야 한다. 종료 시 이런 I/O를 기다리며 이벤트 처리나 종료를 막지 않는다. 현재 FD 기반 경로 검사는 Linux 범위이며 다른 플랫폼은 인벤토리를 미확인으로 표시한다.

회귀 테스트는 루트/별칭 교체, 등록 경로 불일치, 항목·시간 제한, 링크 대상 제외, 접근 실패, 마운트 ID·범위·중첩, 잘못된 경로 표현, 작업자 중단·오래된 결과를 확인한다. 실제 fanotify 권한·컨테이너 마운트 및 운영 파일시스템 종류별 검증은 별도 시험이 필요하다.
