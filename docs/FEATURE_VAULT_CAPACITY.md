# 원격 보관 서버 용량 보호

`argos-vault`는 전역·에이전트별 **논리 바이트와 객체 수**를 제한하고, 신규 게시 전에 파일시스템 여유공간을 확인한다. 한도를 초과하면 신규 업로드는 HTTP 507로 거부한다. v0.7.0은 관리자 번들 취소에 별도 예산을 두어 일반 업로드 포화와 취소 가능 범위를 구분한다. 이미 완성된 동일 에이전트·해시·종류의 재전송과 관리자 조회는 유지하며 기존 객체를 자동으로 삭제하지 않는다.

이 기능은 [원격 보관과 서명 수신증명](FEATURE_REMOTE_VAULT.md)의 저장 경로에 적용된다. 에이전트별 토큰, 관리자 전용 조회 토큰, 고정 공개키 검증 경계는 그대로 유지한다. 용량 계수는 물리 공간 예약이나 WORM 보존을 보장하지 않는다.

## 설정과 기본값

서버 TOML에 다음 항목을 추가한다. 생략한 항목에는 아래 기본값이 적용된다. 클라이언트 설정이나 에이전트의 `argos.toml`에 넣는 항목이 아니다.

```toml
[capacity]
global_max_bytes = 107374182400 # 100 GiB
global_max_objects = 1000000
agent_max_bytes = 10737418240   # 에이전트당 10 GiB
agent_max_objects = 100000
min_free_bytes = 1073741824     # 기본 물리 여유 1 GiB
revocation_max_bytes = 8388608  # 별도 취소 예산 8 MiB
revocation_max_objects = 1000
revocation_agent_max_bytes = 1048576 # 에이전트별 취소 1 MiB
revocation_agent_max_objects = 100
revocation_reserved_free_bytes = 134217728 # 일반 쓰기에 추가 물리 여유 128 MiB
max_scan_entries = 2100000
max_tracked_agents = 4096

[capacity.agent_overrides.web-01]
max_bytes = 21474836480         # web-01은 20 GiB
max_objects = 200000
```

| 설정 | 적용 범위 |
| --- | --- |
| `global_max_bytes`, `global_max_objects` | 모든 에이전트의 일반 풀 합계에 적용. 취소 예약 풀은 별도 |
| `agent_max_bytes`, `agent_max_objects` | 개별 재정의가 없는 에이전트에 적용 |
| `agent_overrides.ID` | 해당 ID의 두 개별 한도를 재정의. 전역 한도도 동시에 적용 |
| `min_free_bytes` | 모든 신규 본문과 80 KiB 게시 여유분을 쓴 뒤 남겨야 할 기본 가용 공간 |
| `revocation_max_bytes`, `revocation_max_objects` | 관리자 `revoked` 기록만 사용하는 추가 전역 논리 예산 |
| `revocation_agent_max_bytes`, `revocation_agent_max_objects` | 추가 취소 예산의 에이전트별 상한. `agent_overrides`와 별개 |
| `revocation_reserved_free_bytes` | 일반 풀 쓰기에만 추가하는 물리 여유 하한. 취소는 이 쿠션을 사용할 수 있지만 기본 `min_free_bytes`는 지킴 |
| `max_scan_entries` | 시작 시 루트와 에이전트 디렉터리에서 읽는 항목 수. 1~2,100,000 |
| `max_tracked_agents` | 메모리에 유지하는 에이전트 계수 수. 1~16,384 |

일반 바이트·객체 한도의 `0`은 신규 저장 허용량이 0이라는 뜻이며 무제한 설정이 아니다. 취소 논리 한도 네 개 중 하나라도 `0`이면 별도 취소 풀과 추가 물리 쿠션이 모두 비활성화되고 취소도 일반 풀을 사용한다. 취소 풀을 유지하면서 물리 쿠션만 끄려면 `revocation_reserved_free_bytes=0`을 사용한다. 기본 물리 여유 검사까지 끄려면 `min_free_bytes=0`도 필요하다. 사용량이 바이트 한도에 도달하면 크기 0인 신규 객체도 거부한다. 에이전트 ID는 기존과 같이 1~128자의 영문·숫자·`-`·`_`만 허용한다. 개별 재정의에는 `max_bytes`와 `max_objects`를 모두 지정한다.

에이전트별로 같은 본문을 각각 보관하면 각각 한 객체와 해당 바이트를 소비한다. 완성된 동일 에이전트·해시의 재전송은 사용량을 늘리지 않는다. 보존 기한이 지난 객체도 삭제 기능이 없으므로 계속 계수한다. 기존 사용량보다 한도를 낮춰 재시작해도 검증 가능한 기존 객체 조회는 가능하다.

## 일반 포화에서의 취소와 업그레이드

일반 풀에는 청크·일반 객체·manifest·완료·`good` 검토가 들어간다. 취소 풀에는 관리자 경로에서 검증한 `revoked` 검토 본문만 들어간다. 임의 업로드나 에이전트 토큰으로 취소 예산을 쓸 수 없다. 기본 최대 논리 용량은 일반 100 GiB/1,000,000개에 취소 8 MiB/1,000개를 **더한 값**이며, 에이전트별 한도도 동시에 적용된다. 취소 풀 자체의 바이트/객체 한도가 차면 추가 취소는 오류로 반환한다. 이미 저장된 동일 요청의 재시도는 추가 용량을 소비하지 않는다.

취소 의도를 SQLite FULL로 먼저 저장한 뒤 추가 기록을 게시한다. 이후 quota·카탈로그 결합 실패가 나면 취소 성공으로 표시하지 않고 해당 번들의 추천·복구를 보류한다. 공간이나 게시 장애를 해결한 뒤 같은 ID/내용으로 재시도한다. 기존 미완료 `good`의 처리와 한도는 [번들 문서](FEATURE_RECOVERY_BUNDLE.md)의 취소 절차를 따른다.

v0.6 이하 설정에서 새 필드를 생략하면 위 예약 기본값이 활성화된다. 기존 `min_free_bytes=0` 설정에도 일반 신규 쓰기에는 추가 128 MiB 쿠션이 적용된다. 시작 시 유효한 과거 취소 제어 객체도 취소 풀로 재분류하므로 일반 풀 사용량은 줄 수 있고 `total`은 유지된다. 이미 취소 예약 한도를 넘는 저장소는 기존 조회를 유지하되 새 취소는 거부한다. 필요한 한도와 여유 공간을 업그레이드 전에 확인한다. 새 취소 의도/대체 보관 상태를 이해하지 못하는 v0.6 서버로 실행 중 저장소를 그대로 낮추지 않는다.

물리 여유는 파일시스템 예약이나 사전 할당이 아니다. 일반 admission은 `min_free_bytes + revocation_reserved_free_bytes + 본문 + 80 KiB`, 취소 admission은 `min_free_bytes + 본문 + 80 KiB`를 검사한다. 다른 프로세스가 공간을 소비하거나 inode가 고갈되면 intent 저장부터 실패할 수 있으므로 ENOSPC 상황에서도 취소가 반드시 기록된다고 보장하지 않는다.

## 관리자 사용량 조회

```bash
argos vault usage --vault-config /etc/argos/vault-admin.toml
```

라이브러리의 `fetch_usage(&VaultConfig)`와 `GET /v1/usage`도 같은 정보를 반환한다. 관리자 토큰만 허용하며 에이전트 업로드 토큰은 HTTP 401로 거부한다. 기존 클라이언트의 HTTPS·loopback 예외·리다이렉트 거부·시간 제한을 적용한다. 사용량 응답은 수신증명처럼 서명된 객체가 아니라 조회 시점의 서버 상태다.

| 응답 필드 | 의미 |
| --- | --- |
| `limits` | 적용 중인 전역·개별 기본 한도와 재정의 |
| `total`, `agents.ID.usage` | 일반·취소 합계: `logical_bytes`, `objects`, `receipted_objects` |
| `normal_usage`, `agents.ID.normal_usage` | 기존 `max_*`를 적용하는 일반 풀 사용량 |
| `revocation_usage`, `agents.ID.revocation_usage` | 별도 취소 풀 사용량. 예약 비활성화 시 0 |
| `agents.ID.limits` | 해당 에이전트에 적용되는 두 개별 한도 |
| `filesystem.supported`, `available_bytes`, `error` | 여유공간 조회 지원 여부·현재 가용 바이트·조회 실패 코드 |
| `reconstruction_complete` | 시작 시 정해진 상한 안에서 계수 재구성을 끝냈는지 여부 |
| `storage_consistent` | 게시/스캔 중 정합성 오류를 발견하지 않았는지 여부 |
| `new_uploads_blocked`, `reasons` | 전역 일반 한도·일반 쓰기용 물리 여유·재구성·정합성 때문에 신규 일반 쓰기를 중지한 상태와 사유 |
| `admission_rejections` | 이번 서버 프로세스가 용량 입장 검사에서 거부한 요청 수. 재시작 시 0 |

`new_uploads_blocked=true`여도 별도 취소 풀과 기본 물리 여유가 남고 정합성이 정상이라면 관리자 취소는 가능하다. `new_uploads_blocked=false`여도 특정 에이전트가 개별 한도에 도달했거나 요청 크기가 남은 허용량보다 크면 거부된다. `admission_rejections`는 인증 오류·잘못된 본문·게시 실패를 모두 세는 통합 HTTP 오류 카운터가 아니다.

`objects`는 읽을 수 있는 논리 객체 파일과 현재 프로세스의 게시 예약을 포함한다. `receipted_objects`는 서명과 경로·에이전트·키 ID·크기가 맞는 수신증명이 있는 객체 수다. 게시 실패 시 둘의 차이가 생길 수 있다. **이 수치는 복구 가능성 전체나 파일 내용의 정상 판정이 아니다.**

## 재시작·동시 요청·저장 실패

서버는 저장소의 `.argos-vault.lock`에 Linux `flock` 배타 잠금을 얻은 후 한 번만 스캔한다. 잠금 파일은 전용 계정 소유 0600 단일 링크 일반 파일이며 서버가 살아 있는 동안 열어 둔다. 같은 저장소에 두 번째 서버를 시작하면 실패한다. 잠금 파일을 실행 중에 삭제하거나 교체해서는 안 된다. 현재 비 Linux 서버는 이 잠금 기능을 지원하지 않는다는 오류로 시작을 거부한다.

시작 스캔은 토큰 목록에 없는 과거 에이전트 디렉터리도 계수한다. 전체 청크 인덱스를 메모리에 올리지 않고 에이전트별 합계와 최대 10,000개 번들의 검증된 제어 객체 수를 보관한다. 항목 수·에이전트 수 상한을 넘거나 권한/파일시스템/읽기 오류로 전체 계수를 확정하지 못하면 `reconstruction_complete=false`로 표시하고 신규 쓰기를 막는다. 조회마다 저장소 전체를 다시 스캔하지 않는다.

각 객체에 대해 일반 파일·소유자·권한·단일 링크·파일 길이를 확인하고, 크기가 제한된 수신증명을 읽어 현재 서버 공개키의 서명과 대상 일치를 검사한다. 청크를 포함한 모든 본문의 SHA-256을 계산하는 전체 무결성 검사는 하지 않는다. 번들 제어 본문은 예외로 해시·서명·에이전트/번들/키 ID 결합을 검증해 소유 번들과 취소 예산을 분류한다. 본문 해시는 관리자 다운로드와 중복 업로드에서 다시 확인한다. 과거 키의 증명을 함께 검증하는 키 회전은 현재 지원하지 않는다.

신규 요청의 한도 확인, 예약 증가, 객체/증명 게시를 동일 저장소 잠금 안에서 처리하므로 동시 업로드가 같은 잔여 용량을 중복 사용하지 않는다. 용량 거부는 디스크 게시 전에 수행한다. 한도와 무관하게 본문 수집은 기존 요청당 최대 64 MiB·동시 허용 4건의 메모리 상한을 적용한다.

게시 실패 시 예약을 즉시 되돌리지 않는다. `publish_failed_restart_required`로 표시하고 신규 쓰기를 중지해 실제로 남았을 수 있는 객체를 과소 계수하지 않는다. 원인을 해결하고 재시작 검사를 통과하면 디스크에서 다시 계산한 값으로 예약을 대체한다. 이미 검증된 객체 쌍은 이 상태에서도 조회·재전송할 수 있으며, 해당 객체 자체가 손상되었다면 성공으로 반환하지 않는다.

객체만 남은 경우, 증명만 남은 경우, 임시 파일이나 유효하지 않은 증명도 신규 쓰기를 중지한다. 서버는 이를 자동 삭제·덮어쓰기·재서명하지 않는다. 관리자가 원인과 남은 파일을 검토한 뒤 조치하고 재시작해야 한다. v0.3.0의 객체 단독 잔여물 재서명 경로는 v0.4.0에서 이 보수적 처리로 바뀌었다. 완성된 두 파일 이후 ACK만 유실된 경우에는 기존 증명을 그대로 재전송한다.

## 계수와 보호의 한계

논리 바이트는 본문 파일 길이의 합이며 수신증명·디렉터리·잠금 파일·임시 파일·파일시스템 메타데이터 크기까지 합산한 값이 아니다. 루트의 설정/키 등 객체 형식 밖 일반 파일도 논리 계수에서 제외한다. 저장소는 전용 디렉터리로 운용하며 다른 용도의 파일을 함께 두지 않는다. 에이전트 디렉터리 안의 예상하지 못한 파일은 정합성 오류로 처리한다.

여유공간은 Linux `fstatvfs`의 현재 사용자 가용 블록 수로 계산한다. 객체와 에이전트 디렉터리가 잠금 파일과 같은 파일시스템인지 확인한다. 여유 하한이 켜진 상태에서 조회 실패나 계산 초과가 발생하면 신규 쓰기를 거부한다. `min_free_bytes=0`이어도 조회 결과와 오류는 사용량 API에 표시한다.

이 검사는 물리 디스크 공간을 예약하지 않으며 다른 프로세스의 동시 소비, 파일시스템 자체의 예약/압축/할당 정책, 사용자 디스크 할당량, inode 고갈을 모두 예측하지 않는다. 80 KiB 여유분은 게시 메타데이터를 위한 보수적 추가량이며 특정 파일시스템의 실제 소비 상한 보장은 아니다. 쓰기·동기화 실패 시에는 성공 증명을 반환하지 않고 신규 쓰기를 중단한다.

잠금과 계수는 같은 저장소를 사용하는 협력적인 서버 프로세스에 대한 경계다. 서버 계정/root가 파일이나 잠금 inode를 직접 바꾸는 행위를 막지 않으며, 실행 중 외부 수정 전체를 감시하지 않는다. NFS 등 원격 파일시스템의 잠금·전원 차단 내구성과 실제 운영 TLS 배포는 아래 로컬 회귀만으로 검증되지 않는다.

## 검증

```bash
CARGO_INCREMENTAL=0 CARGO_TARGET_DIR=/tmp/argos-recovery-target \
  cargo test -p argos-vault --offline --locked server::quota_tests
```

용량 회귀는 실제 loopback HTTP로 개별·전역 바이트/객체 한도, 동시 업로드 예약, 초과 후 동일 수신증명 재전송과 관리자 조회, 조회 인증, 재시작 재구성, 여유 하한, 게시 실패 뒤 읽기 유지, 임시/부분 객체, 스캔 상한, 서명 변조와 유효한 서명의 대상 불일치를 확인한다. 별도 자식 프로세스로 작성자 잠금 경쟁과 해제를 검사한다. 임시 디렉터리만 사용하며 운영 저장소를 변경하거나 실제 디스크를 가득 채우지 않는다. 번들 HTTP 회귀는 일반 풀 포화에서 취소 성공, 취소 전역/개별 바이트·객체 상한, 재시작 후 재분류와 보류 유지, 미완료 정상 검토보다 취소를 우선하는 경계를 추가 확인한다.
