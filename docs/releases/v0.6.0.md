# v0.6.0 — 분할 보관·원격 정상 판정·원본 서버 없는 복구 시험

[v0.5.0](https://github.com/hkjang/ArgosAISecurity/releases/tag/v0.5.0)의 영속 큐와 보관 서버를 연결해, 원본 에이전트 DB 없이 원격 목록에서 백업을 찾아 새 경로에 복구하고 DB 시험까지 수행합니다. 활성 큐·완료 수신증명 이력·작업 임대·예약 전송은 유지합니다.

## 주요 변경

- **분할 백업 보관:** 최대 1GiB의 한 백업 파일을 16MiB 청크로 나눕니다. 구성 목록에 청크 순서·해시·크기와 전체 파일 해시, 원본 경로·버전·참고 판정 이력·선택적 복구 계획을 결합합니다. 모든 청크가 확인돼야 서버가 서명 완료 기록을 게시합니다.
- **원격 목록과 현재 판정:** 관리자 토큰으로 list/show/review를 수행합니다. 최초 판정은 unknown이며, good/revoked는 이전 검토와 연결된 서버 서명 이력으로 추가합니다. 업로드 시점의 원본 주장은 원격 정상 판정을 대신하지 않습니다.
- **원본 서버 없는 복구 시험:** fetch/test는 원본 에이전트 설정·DB 없이 보관 서버와 고정 공개키를 사용합니다. 새 경로의 백업으로 내장 계획의 backup_path만 바꿔 DB 시험을 실행하고 보고서·전체 해시·최종 원격 판정을 재확인합니다.
- **미완료·취소 시 보류:** unknown/revoked·청크 누락·내용 변조·카탈로그/취소 게시 공백이면 일반 복구를 거부합니다. `--evidence-only`는 완성된 조사 자료를 받는 명시적 경로이며 복구 추천은 아닙니다.

## 사용 흐름

```bash
# 현재 계정 소유 전용 부모를 준비합니다.
install -d -m 700 /srv/argos-bundles /srv/argos-restore

argos vault bundle prepare --file /srv/offline/orders.backup \
  --out /srv/argos-bundles/orders-stage \
  --original-path /var/lib/orders/orders.db --version 42 \
  --plan /srv/offline/orders-plan.toml

argos vault --vault-config /etc/argos/vault-upload.toml bundle upload \
  --stage /srv/argos-bundles/orders-stage

# 실제 반환한 에이전트/번들 ID로 조회하고 내용과 계획을 검토합니다.
argos vault --vault-config /etc/argos/vault-admin.toml bundle list --agent-id orders-host
argos vault --vault-config /etc/argos/vault-admin.toml bundle show \
  --agent-id orders-host --id BUNDLE_ID
argos vault --vault-config /etc/argos/vault-admin.toml bundle review \
  --agent-id orders-host --id BUNDLE_ID --request-id review-orders-42 \
  --decision good --actor operator-a --reason '백업 내용과 계획 검토 완료'
argos vault --vault-config /etc/argos/vault-admin.toml bundle test \
  --agent-id orders-host --id BUNDLE_ID --out /srv/argos-restore/orders-drill-42
```

대기열을 사용하면 `bundle enqueue` → `queue drain` → **`bundle publish`** 순서입니다. 기본 큐 바이트 상한은 256MiB이므로 큰 백업에는 `--max-bytes`를 조정하세요. 예약 작업은 청크를 전송하며 구성 목록 완료를 자동 실행하지 않습니다. 각 단계는 하나의 원자적 작업이 아니고, 재시도 시 이미 보관한 같은 해시를 재사용합니다. [전체 CLI 예시](https://github.com/hkjang/ArgosAISecurity/blob/v0.6.0/docs/FEATURE_RECOVERY_BUNDLE_CLI.md)

## 업그레이드와 신뢰 경계

서버와 클라이언트를 함께 업그레이드하고 보관 저장소·카탈로그·서명키·큐를 보존하세요. 번들 카탈로그와 내부 제어 객체를 생성한 저장소는 v0.5 이하 서버로 그대로 되돌리지 않습니다. v0.5의 큐 schema v2와 완료 archive는 유지합니다. 서버 전체 10,000개·에이전트별 1,000개 번들, 번들별 100개 검토 이력 상한이 있으며 마지막 검토 슬롯은 취소에 사용합니다. [저장·용량·중단 경계](https://github.com/hkjang/ArgosAISecurity/blob/v0.6.0/docs/FEATURE_RECOVERY_BUNDLE.md)

이번 묶음은 **백업 한 파일과 메타데이터**를 보존합니다. evidence.json/policy.json/manifest.json 사건 패키지의 자동 원자적 묶음, 로컬 정상본 취소의 원격 자동 전파는 후속입니다. 보관 서버 자체 유실·동일 UID/root의 변조를 막는 WORM도 아닙니다.

서버의 완료·검토 서명과 로컬 시험 결과를 구분합니다. `bundle-test.json`은 단일 JSON 시험 결과이며 `report_authenticated=false`, `trial_executor_authenticated=false`를 유지합니다. `actor` 문자열도 개인 인증이 아닙니다. 실행 ID·계획/백업 해시를 결합한 시험 실행자 서명, AI 사실 필드 대조, 네 실행 파일의 소스 커밋 내장·서명 빌드 기록은 후속입니다.

## 다운로드와 검증

`argos-v0.6.0-linux-x86_64-gnu.tar.gz`와 `SHA256SUMS`를 제공합니다. 네 실행 파일과 설정·문서·systemd 유닛·검증 스크립트·BUILD_INFO.json을 포함하며 GNU/Linux x86_64·glibc 2.39 이상이 필요합니다.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.6.0-linux-x86_64-gnu.tar.gz
cd argos-v0.6.0-linux-x86_64-gnu
./bin/argos --version
python3 scripts/bundle-recovery-scenarios.py --bin-dir "$PWD/bin"
```

워크스페이스 테스트 **248개**, 별도 PostgreSQL 시험 **1개**가 통과했습니다. 릴리즈 바이너리로 번들 7개·보관 4개·영속성 7개·큐 운영 3개·SQLite/PostgreSQL 서비스 복구 15개, **총 36개 시나리오**를 확인했습니다.

번들 시험은 70,332,416바이트(약 67.07MiB) 합성 SQLite 백업을 청크 5개로 보관하고, 원본 디렉터리·DB·계획·stage·큐를 제거한 뒤 원격 목록과 자료만으로 새 경로에 복구했습니다. 부분 업로드 거부·재시작·판정 취소·조사용 받기·행 부족 시험의 추천 거부도 확인했습니다. **동일 loopback 호스트의 새 경로에서 수행한 시험**이며 실제 다른 호스트·원격 TLS·운영 DB 성능이나 전체 서비스 복구를 검증한 결과는 아닙니다.
