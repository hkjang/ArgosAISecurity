# v0.7.0 — 번들 자동 재개·승인 전 격리 시험·취소 우선 처리

[v0.6.0](https://github.com/hkjang/ArgosAISecurity/releases/tag/v0.6.0)의 분할 보관과 원본 서버 없는 복구를 장기 운영 흐름으로 연결합니다. 번들 등록 후 stage가 없어져도 전송과 게시를 재개하며, 미승인 백업을 격리 시험한 결과를 검토에 사용할 수 있습니다.

## 주요 변경

- **영속 번들 작업:** 구성 목록·고유 청크·게시 작업을 원자적으로 등록합니다. 기존 `queue drain`과 예약 전송이 register/complete 단계를 재시도하고 작업자 종료·응답 유실 후 임대가 만료되면 재개합니다. `queue jobs`, `show-bundle`, `status.bundle_jobs`로 상태를 조회합니다.
- **승인 전 격리 시험:** 완료된 unknown 번들에 `bundle test --preapproval`를 제공합니다. SQLite는 필요한 실행 파일·라이브러리·읽기 전용 백업만 노출한 Linux namespace에서, PostgreSQL은 기존 전용 격리 경로에서 검사합니다. 시험 성공은 원격 good 판정을 생성하지 않으며 일반 복구는 계속 거부됩니다.
- **취소 우선 처리:** 일반 저장 예산과 별도로 한정된 취소 예산과 디스크 여유 정책을 둡니다. 취소 의도를 먼저 영속 기록해 추천을 보류하고, 앞선 정상 승인 요청이 게시 중단·용량 부족으로 멈춘 경우도 취소가 진행되도록 처리합니다.
- **번들별 장애 분리:** 서명된 제어 기록의 소유 번들을 검증할 수 있으면 해당 번들만 `unavailable`로 표시합니다. 독립적으로 검증 가능한 다른 번들은 조회·복구할 수 있습니다. 귀속 불명·카탈로그 유실·전체 구조 오류는 전역 보류합니다.
- **동시 제어와 TLS:** 큰 청크 검증을 공용 저장소 잠금 밖에서 수행하고 게시 직전 상태를 재확인합니다. 사설 CA 목록을 명시하는 `tls_ca_pem`을 지원하며 체인·호스트명 검증과 큐의 CA 고정을 유지합니다.

## 사용 흐름

```bash
# prepare로 만든 stage를 영속 등록합니다. 큰 백업은 큐 바이트 한도를 조정합니다.
argos vault --vault-config /etc/argos/vault-upload.toml bundle enqueue \
  --stage /srv/argos-bundles/orders-stage --directory /var/lib/argos/upload-queue
argos vault --vault-config /etc/argos/vault-upload.toml queue drain \
  --directory /var/lib/argos/upload-queue --max-items 16
argos vault queue jobs --directory /var/lib/argos/upload-queue

# 완료된 unknown 번들을 새 출력 경로에서 격리 시험합니다.
argos vault --vault-config /etc/argos/vault-admin.toml bundle test \
  --agent-id orders-host --id BUNDLE_ID \
  --out /srv/argos-restore/orders-preapproval --preapproval

# 시험 결과와 원본 근거를 검토한 뒤 별도로 승인합니다.
argos vault --vault-config /etc/argos/vault-admin.toml bundle review \
  --agent-id orders-host --id BUNDLE_ID --request-id review-orders-42 \
  --decision good --actor operator-a --reason '격리 시험 결과와 원본 근거 검토 완료'
```

수동 `publish`와 직접 `upload`는 계속 지원합니다. [자동 재개](https://github.com/hkjang/ArgosAISecurity/blob/v0.7.0/docs/FEATURE_BUNDLE_JOBS.md) · [승인 흐름과 상태 해석](https://github.com/hkjang/ArgosAISecurity/blob/v0.7.0/docs/FEATURE_BUNDLE_OPERATIONS.md)

## 업그레이드와 한계

작업자를 모두 중지하고 큐·보관 객체·카탈로그·서명키를 보존한 뒤 서버와 클라이언트를 함께 교체하세요. 첫 큐 변경 작업이 schema v1/v2를 v3로 이전합니다. 이전 후 구버전 작업자를 같은 큐에 연결하지 않습니다. 번들 enqueue 출력은 `chunk_items`와 작업 `state`/`phase`로 변경됐습니다. 완료된 작업도 보존하며 큐당 번들 작업 상한은 1,000개입니다.

취소 풀의 기본 추가 한도는 서버 8MiB/1,000개, 에이전트 1MiB/100개이며 일반 저장에는 기존 최소 여유 공간 외에 128MiB 여유 정책이 추가됩니다. 실제 디스크 공간을 선점하는 기능은 아닙니다. 물리 ENOSPC·저장장치 고장까지 영속 성공을 보장하지 않으며, 실패 응답을 완료된 취소로 취급하면 안 됩니다. [용량과 이전 경계](https://github.com/hkjang/ArgosAISecurity/blob/v0.7.0/docs/FEATURE_VAULT_CAPACITY.md)

승인 전 SQLite 시험에는 비 root Linux GNU x86_64·신뢰한 bubblewrap과 user namespace·Linux 5.11 이상 close_range 지원가 필요합니다. 격리할 수 없으면 실패하며 호스트 직접 실행으로 대체하지 않습니다. 시험 보고서는 무서명이고 `report_authenticated=false`, `trial_executor_authenticated=false`입니다. `actor` 문자열은 개인 인증이 아닙니다. 서버 `recommended`도 DB 시험 통과나 현재 모든 청크의 가용성을 뜻하지 않습니다.

키 교체·보관 서버 재해복구·주기적 실물 검사·개인별 권한·시험 실행자 서명은 후속 범위입니다. 실제 3개 호스트의 배포·운영 인증서·물리 네트워크 장애는 이번 검증에 포함하지 않았습니다.

## 다운로드와 검증

`argos-v0.7.0-linux-x86_64-gnu.tar.gz`와 `SHA256SUMS`를 제공합니다. 네 실행 파일, 설정·문서·systemd 예제·시나리오 도구·BUILD_INFO.json을 포함하며 GNU/Linux x86_64·glibc 2.39 이상이 필요합니다.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.7.0-linux-x86_64-gnu.tar.gz
cd argos-v0.7.0-linux-x86_64-gnu
./bin/argos --version
python3 scripts/bundle-operations-scenarios.py --bin-dir "$PWD/bin" \
  --report /tmp/argos-bundle-operations-new.json
```

워크스페이스 **275개**, 별도 PostgreSQL·SQLite 격리 시험 **2개**, 릴리스 바이너리 시나리오 **41개**가 모두 통과했습니다. 시나리오는 보관 4·영속성 7·큐 운영 3·서비스 복구 15·대용량 번들 7·TLS/자동 재개/승인 전 시험 5개입니다. 새 스크립트는 `--pg-root /path/to/trusted/postgresql/root`를 추가하면 PostgreSQL 시험까지 실행합니다.

stage 삭제와 게시 직전 SIGKILL·실제 임대 만료·완료 응답 유실·서버 재시작 후 자동 게시를 확인했습니다. SQLite·PostgreSQL 모두 unknown 시험 성공 후 일반 복구는 계속 거부했습니다. 격리 자식의 상속 파일·소켓 차단, 미완료 승인보다 취소 우선 처리, 일반 용량 포화 중 취소, A 번들의 게시 실패와 정상 B 분리, 긴 완료 검사와 취소 동시 처리도 검증했습니다.

대용량 회귀는 약 67MiB(70,332,416바이트) SQLite 백업·5청크로 원본 자료 삭제 뒤 복구했습니다. TLS와 격리 시험은 **같은 호스트**의 임시 프록시·namespace에서 수행했습니다. 실제 서버 3대 검증은 남아 있습니다.
