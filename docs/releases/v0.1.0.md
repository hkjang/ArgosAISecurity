# v0.1.0 — 검증 가능한 Linux 보안 플랫폼

ArgosAISecurity의 첫 GitHub 릴리즈입니다. 탐지 점수와 실제 대응 결과를 구분하고, 검토된 정상 복구 지점으로 복구를 시험하며, 새 정책의 영향을 과거 증거로 비교할 수 있습니다. 자동 차단은 기본 비활성입니다.

## 주요 변경

- **자동 차단 정확성:** fanotify/notify별 점수, 도달 불가능한 임계치 경고, 알림 중복 억제와 독립된 대응 판단. PID·시작 시각·부팅 ID와 pidfd로 프로세스 신원을 확인하고 종료 결과를 감사 기록에 남깁니다.
- **안전한 복구:** 정상본 지정·취소, 공격 이전 정상본 추천, 별도 경로 미리보기, 원본 유지 복구 시험과 준비도 보고서. 검토된 정상본은 보존하며 소유권을 유지하고 setuid/setgid를 제거합니다.
- **정책 사전 검증:** 저장 이벤트·엔트로피·프로세스 맥락으로 기존/후보 정책의 탐지·차단 예상 대상과 차이를 비교합니다. 실제 정책 적용이나 차단 없이 근거 ID와 조회 누락을 표시합니다.
- **검증·수집 일관성:** 정책을 한 번 읽은 동일 바이트로 서명 검증하고 파싱합니다. 프로세스 폴링은 기존 PID의 실행 파일·명령행·실효 UID 변화도 이벤트로 기록합니다. 폴링 사이에 끝난 실행·권한 변화는 놓칠 수 있습니다.
- **정상 작업과 초기 공격 구분:** 승인 기간·경로·실행 파일·계정이 모두 일치하는 작업에 한해 규칙을 조정합니다. 미끼 파일 변조는 별도 고위험 신호로 평가합니다.
- **운영 신뢰성:** 제한 큐와 별도 백업 작업자, 센서/백업 누락 지표, 주기적 생존 신호, SQLite 영속 전송 대기열, 재시도와 중앙 중복 제거.
- **인증과 격리:** 관리자 조회/에이전트 수집 인증 분리, 명시적 loopback 개발 모드, 비밀값 마스킹. IPv4/IPv6의 INPUT·OUTPUT·FORWARD에서 지정 관리 연결만 허용합니다.
- **근거 기반 조사:** 기간·PID별 조회와 근거 ID, 조회 누락 표시, Anthropic/Ollama 제공자·주소·모델 설정, 조회형 MCP, 시간순 사건 HTML과 복구 준비도 HTML.

## 기존 main 설정에서 달라지는 점

1. 중앙 운영 서버에는 `ARGOS_CENTRAL_TOKEN` 관리자 토큰과 `--agent-tokens` JSON 파일의 서로 다른 에이전트별 토큰이 필요합니다. 에이전트 `[central].token`은 해당 에이전트 토큰입니다. 인증 없는 개발 서버는 `--development --listen 127.0.0.1:8420`으로 명시합니다.
2. 기존 백업과 시작 시 baseline은 자동으로 정상본이 되지 않습니다. `restore --list` → `--version ID --preview NEW_PATH`로 검토한 뒤 `--mark-good ID --note TEXT`로 정상본을 지정하세요. 기본 복구와 `--before-ms` 복구는 정상 판정 버전만 선택합니다. 기존 이벤트/백업 DB에는 추가 스키마가 적용되므로 업데이트 전 DB·백업 저장소를 보관하세요.
3. 격리 허용 규칙은 `--allow in:192.0.2.20:22`, `--allow out:10.0.0.5:8420`처럼 방향·IP·TCP 포트를 지정합니다. IPv6는 `out:[2001:db8::10]:443` 형식입니다. 기존 연결이나 중앙 서버 호스트를 포괄적으로 자동 허용하지 않습니다. 먼저 `--dry-run`으로 계획을 확인하세요.
4. AI 모델은 `[ai].model` 또는 `ARGOS_AI_MODEL`에 명시해야 합니다. Ollama에는 기본적으로 외부 제공자 키를 보내지 않습니다.
5. 고정된 Linux 의존성은 Rust 1.86 이상을 요구합니다. 이 릴리즈는 Rust 1.93.1로 빌드·검증했습니다.

## 다운로드와 사용

`argos-v0.1.0-linux-x86_64-gnu.tar.gz`에는 `argos`, `argos-agent`, `argos-central`, 예제 설정, systemd 유닛, 라이선스, 주요 운영 문서와 빌드 정보가 포함됩니다. `SHA256SUMS`로 다운로드를 검증하세요.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.1.0-linux-x86_64-gnu.tar.gz
cd argos-v0.1.0-linux-x86_64-gnu
./bin/argos --version
./bin/argos --help
```

첨부 바이너리는 **GNU/Linux x86_64, glibc 2.39 이상**용입니다. 동적 라이브러리와 개별 실행 파일의 요구 버전은 패키지 `BUILD_INFO.json`을 확인하세요. [설치 안내](https://github.com/hkjang/ArgosAISecurity/blob/v0.1.0/docs/INSTALL_BINARY.md)에 설정·서비스 설치 절차가 있습니다. 다른 환경에서는 태그 소스에서 `cargo build --release --workspace --locked`로 빌드할 수 있습니다. Windows/macOS 바이너리는 이번 릴리즈에 포함하지 않습니다. 자동 차단에는 pidfd를 지원하는 Linux 커널과 필요한 권한이, 네트워크 격리에는 iptables/ip6tables 계열 도구가 필요합니다.

## 검증

- 워크스페이스 단위/회귀 테스트 **96개 통과**.
- 릴리즈 바이너리로 실제 파일 변경 → 탐지 → 정상본 검토/지정 → 미리보기 → 정상 내용 복구 → 정책 재생·서명/변조 거부.
- 인증·에이전트 신원·중복 제거·생존 신호, 조회형 MCP 읽기 전용, HTML 보고서의 데이터 주입 방지.
- 별도 사용자/네트워크 네임스페이스에서 실제 IPv4/IPv6 패킷으로 관리 연결 유지, 기존/새 의심 연결·전달 경로 차단, 재적용·해제 검증. 호스트 방화벽은 변경하지 않았습니다.
- 프로세스 시작 신원이 다르면 거부하고, 같은 신원인 테스트 자식만 pidfd로 종료 확인.

## 검증 범위와 후속 과제

실제 fanotify 권한 환경의 전체 수집·차단 경로, 운영 처리량/CPU/I/O, 사내 LLM 품질과 분석가의 조사 시간은 배포 환경에서 추가 검증이 필요합니다. 정상 작업 테스트의 오탐 감소 결과는 고정 시나리오이며 운영 오탐률의 실측이 아닙니다.

ITSM 자동 연동, Suricata/Zeek 연결 상관분석, eBPF, mTLS, Kubernetes, 중앙 자동 정책 배포는 후속 단계입니다. 격리는 패킷을 차단하며 소켓 객체 자체를 삭제하지 않습니다. 파일 백업은 원자적 파일시스템 스냅샷이 아니며 ACL/xattr/SELinux 메타데이터의 완전한 복원은 지원하지 않습니다.

정책 다운그레이드·재사용 방지, 저속·분산 공격 탐지, Linux 설정 의미 분석, 사고별 복구 지점 보존 고정 등의 추가 제안은 [후속 개발 계획](https://github.com/hkjang/ArgosAISecurity/blob/v0.1.0/docs/ROADMAP.md)에 완료 기준과 함께 정리했습니다. 현재 구현된 정상본 보존은 사고별 보존 잠금이나 별도 해제 승인 기능과는 구분됩니다.
