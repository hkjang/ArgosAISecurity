# v0.3.0 — 보호 공백·DB 복구·원격 보관 검증

[v0.2.0](https://github.com/hkjang/ArgosAISecurity/releases/tag/v0.2.0)의 탐지·정책 신뢰·정상본 보존에 운영자가 직접 실행할 수 있는 검증 경로를 추가했습니다. 자동 차단은 계속 기본 비활성입니다.

## 주요 변경

- **보호 공백 검사:** 별도 작업자가 경로 접근·루트 교체·마운트 변경과 검사 상한을 확인합니다. 오래된 결과와 작업자 종료도 보호 저하로 표시합니다. `coverage probe`는 작은 시험 파일을 쓰고 새 이벤트 ID가 로컬 DB에 도달했는지 확인합니다.
- **네이티브 DB 복구 시험:** `service-recovery test`가 SQLite Backup API 또는 PostgreSQL custom 아카이브를 새 작업 경로에 복원합니다. 스키마·최소 행 수·제약·쓰기 롤백을 검사하고 실측 복원/검사 시간을 남깁니다. PostgreSQL은 Linux bubblewrap의 네트워크 격리와 새 클러스터를 사용합니다.
- **별도 서버 보관:** 새 `argos-vault` 실행 파일이 에이전트별 업로드 토큰과 관리자 조회 토큰을 분리합니다. 삭제·덮어쓰기 API 없이 객체를 저장하고 Ed25519 수신증명을 발급합니다. CLI는 고정 공개키·본문 해시·대상을 검사하며 정상 백업과 증거 패키지 어댑터를 제공합니다.
- **승인 예외 감사:** `policy audit-exceptions`는 현재 기준 정책을 같은 저장 이벤트 스냅샷에 재생해 매칭·만료·넓은 범위·표본 누락을 보여 줍니다. 모든 예외를 제거한 정책의 탐지·예상 대응 차이도 비교합니다.
- **AI 인용 검사:** `ask`와 `explain`이 사실·추정·미확인 형식으로 응답받고 실제 제공한 근거의 종류·ID·시각·로컬 출처와 대조합니다. 잘못된 인용·형식은 거부하고 조회 누락 안내는 앱이 직접 출력합니다.

## v0.2.0에서 업그레이드

1. 서비스를 중지하고 설정·이벤트 DB·백업·정책 상태를 보관한 뒤 바이너리를 교체하세요. 서명 정책의 버전·키·대상 규칙과 기존 정상본 판정은 유지됩니다.
2. `[coverage]`는 기본 활성입니다. 기존 설정도 30초 간격·전체 10,000개 항목 상한으로 검사합니다. 큰 보호 트리·링크·읽지 못한 경로·하위 마운트는 공백 또는 미확인으로 표시할 수 있습니다. 전체 감시 성공이라는 의미로 해석하지 마세요. [보호 공백](https://github.com/hkjang/ArgosAISecurity/blob/v0.3.0/docs/FEATURE_COVERAGE.md)
3. AI 제공자 설정은 그대로 사용하지만 모델은 문서의 구조화 JSON 응답을 따라야 합니다. 따르지 못한 모델이나 잘못된 인용은 오류로 처리하며 원문 답변을 대신 표시하지 않습니다. [AI 검사](https://github.com/hkjang/ArgosAISecurity/blob/v0.3.0/docs/FEATURE_AI_VALIDATION.md)
4. 서비스 복구·원격 보관은 명시적인 별도 CLI 작업입니다. 자동 예약·업로드는 제공하지 않습니다. PostgreSQL 도구와 bubblewrap은 패키지에 포함하지 않습니다. PostgreSQL 18.6과 Debian 계열 x86_64 경로에서 실제 검증했습니다. [복구 계획](https://github.com/hkjang/ArgosAISecurity/blob/v0.3.0/docs/FEATURE_SERVICE_RECOVERY.md)
5. 보관 서버는 별도 호스트와 권한으로 운영하고 전용 0700 경로·0600 설정/키, TLS 프록시와 고정 공개키를 준비하세요. 클라이언트의 평문 HTTP는 명시적으로 허용한 loopback 시험에만 사용할 수 있습니다. [보관 구성](https://github.com/hkjang/ArgosAISecurity/blob/v0.3.0/docs/FEATURE_REMOTE_VAULT.md)

## 다운로드

이전 릴리즈와 같은 형식으로 `argos-v0.3.0-linux-x86_64-gnu.tar.gz`와 `SHA256SUMS`를 제공합니다. `argos`, `argos-agent`, `argos-central`, **`argos-vault`**와 설정·운영 문서·시험 스크립트·라이선스·`BUILD_INFO.json`을 포함합니다.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.3.0-linux-x86_64-gnu.tar.gz
cd argos-v0.3.0-linux-x86_64-gnu
./bin/argos --version
python3 scripts/assurance-scenarios.py --bin-dir "$PWD/bin"
python3 scripts/vault-scenarios.py --bin-dir "$PWD/bin"
python3 scripts/service-recovery-scenarios.py --bin-dir "$PWD/bin"
```

GNU/Linux x86_64용이며 glibc 요구사항과 설치 절차는 [설치 안내](https://github.com/hkjang/ArgosAISecurity/blob/v0.3.0/docs/INSTALL_BINARY.md)를 확인하세요. 다른 환경은 태그 소스로 `cargo build --release --workspace --locked`를 실행합니다.

## 검증 범위

- 워크스페이스 단위·회귀 **188개 통과**, 별도 PostgreSQL 18.6 네이티브 복원 시험 **1개 통과**.
- 기존 스모크·중앙 인증/수집/MCP 시험과 **8개 보안 시나리오**.
- 실제 notify 전달·루트 교체·수집 중단, 예외 제거 비교, Ollama 모의 서버를 이용한 실제 AI CLI의 **5개 시나리오**.
- 감사 파일·정상본·증거 패키지의 보관/복원과 변조 거부 **4개 시나리오**.
- SQLite/PostgreSQL 원본 유지·스키마/행 수·쓰기 롤백·기존 경로/잘못된 입력 거부·타임아웃/서버 정리 등 **15개 복구 검사**. 외부 모델이나 운영 DB를 호출하지 않았습니다.

자세한 실행 수와 재현 명령은 [검증 기록](https://github.com/hkjang/ArgosAISecurity/blob/v0.3.0/docs/PLATFORM_VALIDATION.md)을 따릅니다.

경로 검사와 한 번의 probe는 커널 감시 전체를 인증하지 않습니다. DB 검사 성공도 애플리케이션 전체의 업무 정상화를 증명하지 않으므로 RPO·서비스 RTO는 미확인으로 남깁니다. 보관 서버의 디스크 관리자에 대한 WORM·삭제 방지와 자동 복제는 제공하지 않습니다. 예외 감사는 현재 정책의 재생이지 사건 당시 실행 원장이 아닙니다. 인용 검사는 AI 문장의 의미적 진실성까지 보증하지 않습니다. 실제 fanotify 전체 경로·운영 탐지율/성능·사내 모델 품질은 배포 환경에서 별도 검증해야 합니다.
