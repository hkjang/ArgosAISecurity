# v0.2.0 — 정책 신뢰와 Linux 행위 분석 강화

[v0.1.0](https://github.com/hkjang/ArgosAISecurity/releases/tag/v0.1.0)의 차단·복구 검증 기반에 정책 재사용 방지, 저속·분산 행위 분석, Linux 설정 의미 감시와 사건별 증거 보존을 추가했습니다. 자동 차단은 기본 비활성이며, 다중 시간 구간·내용 표본 분석은 설정에서 선택 활성화합니다.

## 주요 변경

- **정책 신뢰:** 동일 바이트 서명 검증 후 정책 ID·버전·유효기간·대상 호스트/그룹·서명 키 ID와 설정을 검사합니다. 수락 원문·설정·최대 버전·감사 기록을 원자적으로 저장하고, 이전 버전이나 내용이 다른 동일 버전은 거부합니다. 동일 버전·동일 해시는 유효한 재시작에만 허용합니다.
- **승인된 롤백:** 과거 설정으로 돌아갈 때도 새로운 높은 버전과 이전 정책 해시·승인 ID·사유가 필요합니다. 실행 중 정책 기간을 벗어나면 자동 차단을 중단하고 수락한 탐지 설정을 유지하며 보호 저하를 표시합니다.
- **저속·분산 탐지:** 10/60/600초 시간창과 프로세스 인스턴스·유효 계정·보호 경로·확인된 부모 계보를 분석합니다. 여러 PID의 합산 경보만으로 특정 PID를 종료하지 않습니다. 메모리 상한과 근거 누락을 표시하며 과거 정책 재생에도 같은 로직을 적용합니다.
- **부분 암호화 분석:** 총 읽기 예산 안에서 앞·중간·끝을 표본화하고 파일 유형 힌트·이전 관측 대비 엔트로피 변화를 저장합니다. 비교 가능한 압축 파일은 높은 엔트로피만으로 암호화 신호를 만들지 않습니다. 이전 관측은 정상본 판정이 아닙니다.
- **Linux 의미·자격 감시:** 지정한 `authorized_keys`, sudoers, cron, systemd 파일의 의미·순서·소유권·권한 변화를 구분합니다. 실제/유효/저장/filesystem UID·GID와 capability 변화를 프로세스 근거에 저장하고, 파일 이벤트에 최대 4단계 부모 신원을 연결합니다.
- **사건별 복구 보존:** 정상본 판정과 별도로 사건 참조를 고정하고 다중 사건 참조·해제 승인·감사 기록을 유지합니다. 탐지와 보존 요청을 함께 저장한 뒤 별도 작업자가 처리하므로 백업 DB 잠금이 다음 탐지를 지연시키지 않습니다. 재시작 재시도와 10,000건 대기열 상한·누락 지표를 제공합니다.
- **사고 증거 패키지:** `evidence-export`로 근거·대응 이력·마지막 수락 정책 스냅샷과 파일별 SHA-256 manifest를 내보냅니다. 기본적으로 경로·명령행·자유 서술·문자열 식별자를 가리고, `evidence-verify`로 무결성을 확인합니다.
- **재현 도구:** 임시 파일과 자식 프로세스를 사용하는 `scripts/security-scenarios.py`가 예상 결과와 실제 결과를 비교해 JSON 보고서를 작성합니다.

## v0.1.0에서 업그레이드

1. **서명 정책 설정 전환이 필요합니다.** `policy.pubkey`만 사용하는 기존 정책은 운영 활성화에서 거부됩니다. `[policy.trusted_keys]`에 키 ID와 공개키를 등록하고, 로컬 정책 ID·서버 ID·그룹 및 정책의 버전·기간·대상·키 ID를 지정한 뒤 다시 서명하세요. 잘못된 정책은 에이전트 시작을 중단하며 기본 설정으로 전환하지 않습니다. [정책 설정 이전](https://github.com/hkjang/ArgosAISecurity/blob/v0.2.0/docs/FEATURE_POLICY.md#이전-설정에서-이전하기)
2. 정책·서명은 심볼릭 링크나 FIFO가 아닌 일반 파일이어야 합니다. 정책 상태의 기본 경로는 `<db_path>.policy-state/state.sqlite3`이며, 현재 실행 계정 소유의 전용 디렉터리 `0700`과 파일 `0600`을 요구합니다. 버전을 초기화하려고 상태를 삭제하지 마세요.
3. 업데이트 전에 에이전트를 중지하고 설정·이벤트 DB·백업 저장소·기존 정책 상태를 보관하세요. 이벤트 JSON·사건 보존·대기열용 스키마가 추가됩니다. **v0.1.0에서 검토한 정상본 판정은 유지**됩니다. 미검토 백업을 정상본으로 자동 승격하지 않습니다.
4. `policy verify`는 읽기 전용 사전 확인이며 영속 버전 검사나 활성화를 수행하지 않습니다. `policy status`는 수락·거부 이력, `policy show`는 마지막 수락 정책을 표시합니다. 서명 정책의 재생 기준도 후보 파일이 아닌 수락 상태입니다.
5. `[detection.multi_window]`, `[detection.content_sampling]`을 선택 활성화하고, `[semantic].files`에는 `watch_paths` 안의 지원 파일을 절대 경로로 지정하세요. [예제 설정](https://github.com/hkjang/ArgosAISecurity/blob/v0.2.0/config/argos.example.toml)

서명 정책을 사용하지 않는 로컬 설정은 계속 지원합니다. 빌드 요구사항은 Rust 1.86 이상이며 이번 릴리즈는 Rust 1.93.1로 검증했습니다.

## 다운로드와 사용

이전 릴리즈와 같은 형식의 `argos-v0.2.0-linux-x86_64-gnu.tar.gz`와 `SHA256SUMS`를 제공합니다. 패키지에는 `argos`, `argos-agent`, `argos-central`, 설정·systemd 예제, 운영 문서, 시험 스크립트, 라이선스와 소스 커밋·실행 파일 해시를 담은 `BUILD_INFO.json`이 포함됩니다.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.2.0-linux-x86_64-gnu.tar.gz
cd argos-v0.2.0-linux-x86_64-gnu
./bin/argos --version
python3 scripts/security-scenarios.py --bin-dir "$PWD/bin"
```

첨부 바이너리는 **GNU/Linux x86_64, glibc 2.39 이상**용입니다. 다른 환경에서는 태그 소스로 `cargo build --release --workspace --locked`를 실행하세요. 개별 동적 라이브러리 요구사항은 `BUILD_INFO.json`, 설치 절차는 [Linux 바이너리 설치](https://github.com/hkjang/ArgosAISecurity/blob/v0.2.0/docs/INSTALL_BINARY.md)를 참고하세요.

## 검증

- 워크스페이스 단위·회귀 테스트 **144개 통과**.
- 릴리즈 바이너리로 **8개 보안 시나리오 통과**: 의미 변화·정상 주석 구분, 자동 사건 보존, 같은 PID 실행 변경·자격 정보, 승인 해제, 증거 패키지, 분산 정책 재생, 영속 정책 신뢰.
- 실제 파일 변경·탐지·정상본 복구·정책 서명/변조 거부, 중앙 인증·중복 제거·생존 신호, 조회형 MCP·HTML 안전성 시험 통과.
- 백업 DB 잠금 중 탐지 기록과 보존 작업 분리, 재시작·중복 ACK·대기열 상한 회귀 검증.

## 검증 범위와 후속 과제

다중 표본과 `/proc` 폴링은 파일 전체나 모든 실행·권한 변화를 포착하지 못합니다. 표본은 이벤트보다 늦게 읽은 내용을 반영할 수 있으며 특정 PID가 그 바이트를 썼다는 증명이 아닙니다. 설정 의미 분석은 완전한 Linux 유효 설정 평가기가 아니고 include 자동 추적·서비스 적용 확인은 제공하지 않습니다.

정책 상태의 `active`는 마지막 수락 설정이며 실제 센서 가동 성공이나 사건 시점 실행 정책의 증명이 아닙니다. 보존 해제의 승인 문자열은 외부 승인자 인증을 대신하지 않습니다. 로컬 관리자/root의 상태 삭제·전체 디스크 롤백에는 별도 외부 신뢰 경계가 필요합니다. 증거 해시는 파일과 manifest의 일치만 검증하며 발급자 서명은 아닙니다.

실제 fanotify 권한 환경의 전체 수집·차단 경로, 운영 탐지율·처리량·CPU/I/O는 배포 환경에서 추가 검증해야 합니다. 실행 파일 패키지 신뢰·서비스 영향·자원 자동 조절·중앙 자동 정책 배포는 후속 범위입니다.
