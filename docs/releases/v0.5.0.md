# v0.5.0 — 큐 수명주기·작업 임대·예약 전송

[v0.4.0](https://github.com/hkjang/ArgosAISecurity/releases/tag/v0.4.0)의 보관 대기열을 장기 운영할 수 있도록 완료 이력과 활성 작업을 분리했습니다. 느린 네트워크 요청 중에도 새 파일을 등록하고 다른 항목을 처리할 수 있습니다.

## 주요 변경

- **완료 수신증명 보관소:** 활성 큐의 기본 1,000개 한도는 대기/임대 항목만 셉니다. 검증된 완료 이력은 같은 DB의 별도 archive로 원자적으로 이동하며 중복 판정과 ID 조회에 계속 사용합니다.
- **항목별 임대:** 짧은 트랜잭션에서 임대를 얻은 뒤 파일 잠금과 DB를 닫고 전송합니다. 작업자 중단 후 만료된 임대를 재처리하고, 오래된 작업자의 ACK는 상태 변경·본문 삭제에 사용할 수 없습니다.
- **이력 내보내기:** `queue export-archive`는 완료 수신증명을 새 JSONL 파일로 내보냅니다. `verify-archive`는 큐 DB 없이 구조·해시·개별 수신증명 서명을 확인합니다. 원본 이력은 삭제하지 않습니다.
- **예약 전송·오류 구분:** 선택 설치하는 systemd service/timer를 제공합니다. 인증·용량·호출 제한·서버·연결/시간 초과·무결성 오류를 구분하며 원격 오류 본문·토큰·주소를 오류에 보존하지 않습니다.

## 업그레이드와 운영

1. v0.4.0의 모든 큐 작업자를 종료하고 전용 큐 디렉터리를 보관한 뒤 바이너리를 교체하세요. 첫 변경 작업이 기존 완료 수신증명을 검증하고 DB를 schema v2로 원자적으로 이전합니다. 이후 구버전 바이너리를 같은 큐에 사용하지 마세요.
2. 활성 항목 한도 외에 완료 이력과 활성 예약 슬롯을 합한 **100,000개 상한**이 있습니다. `archive_slots_available`을 확인하세요. 상한에 도달하기 전에 완료 이력을 내보내고 기존 큐를 보존한 뒤 새 큐 경로를 사용하는 절차가 필요합니다. 새 큐는 이전 큐의 로컬 중복 판정 기록을 공유하지 않습니다.
3. 임대는 클라이언트 요청 제한에 30초를 더한 기간입니다. 실패 시 기존 backoff와 임대 만료를 따르며 파일을 자동 삭제하지 않습니다. 시스템 시계 변경과 저장소 I/O는 실제 재처리 시각에 영향을 줍니다.
4. 예약 전송은 전용 계정·0700 큐·0600 설정을 준비한 뒤 명시적으로 활성화하세요. 예제는 한 번에 16건, 부팅 후/직전 작업 종료 후 약 1분 간격입니다. 에이전트의 자동 파일 등록이나 중앙 상태 통합은 포함하지 않습니다. [예약 구성](https://github.com/hkjang/ArgosAISecurity/blob/v0.5.0/docs/FEATURE_VAULT_SCHEDULER.md)

내보낸 목록은 서명되지 않았습니다. 개별 수신증명의 유효성과 목록 형식/해시를 확인하는 것이며, 전체 사건 목록의 출처나 누락 없는 완전성을 인증하지 않습니다. 상세 절차는 [큐 운영](https://github.com/hkjang/ArgosAISecurity/blob/v0.5.0/docs/FEATURE_VAULT_QUEUE.md)을 참고하세요.

## 다운로드·검증

이전 형식과 같이 `argos-v0.5.0-linux-x86_64-gnu.tar.gz`, `SHA256SUMS`를 제공합니다. 네 실행 파일과 문서·설정·systemd 유닛·검증 스크립트·`BUILD_INFO.json`을 포함하며 GNU/Linux x86_64·glibc 2.39 이상이 필요합니다.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.5.0-linux-x86_64-gnu.tar.gz
cd argos-v0.5.0-linux-x86_64-gnu
./bin/argos --version
python3 scripts/queue-operations-scenarios.py --bin-dir "$PWD/bin"
python3 scripts/durability-scenarios.py --bin-dir "$PWD/bin"
```

워크스페이스 테스트 235개와 별도 PostgreSQL 시험 1개가 통과했습니다. 릴리즈 바이너리로 보관 4개·영속성 7개·큐 운영 3개·보안 8개·보호/AI 5개 및 기존 스모크·중앙/MCP 경로를 확인했습니다. 실행한 회귀·통합 시험과 한계는 [검증 기록](https://github.com/hkjang/ArgosAISecurity/blob/v0.5.0/docs/PLATFORM_VALIDATION.md)을 참고하세요. 예약 유닛의 구문과 동일 drain 명령은 검증하지만 운영 호스트의 타이머를 자동 활성화하지 않습니다. 원격 파일시스템·전원 차단·동일 UID/root의 삭제 방지는 별도 검증 범위입니다.
