# v0.4.0 — 보관 재전송·용량 보호·복구 보고서 재검증

[v0.3.0](https://github.com/hkjang/ArgosAISecurity/releases/tag/v0.3.0)의 원격 보관과 DB 복구 시험에 통신 단절·용량 초과·검사 조건 변경을 확인하는 기능을 추가했습니다. 자동 차단은 기본 비활성입니다.

## 주요 변경

- **영속 보관 대기열:** `vault queue enqueue`는 당시 파일 바이트와 대상 서버·에이전트·공개키를 고정합니다. `drain`이 재시도 시각에 도달한 항목을 처리하고 서명 수신증명을 저장한 뒤 스냅샷을 정리합니다. 원본 변경·삭제 뒤에도 같은 바이트를 전송하며 토큰은 큐에 저장하지 않습니다. 정상본·증거 패키지 등록 어댑터와 읽기 전용 상태/항목 조회를 제공합니다.
- **보관 용량 보호:** 전체·에이전트별 논리 바이트/객체 수와 최소 디스크 여유를 검사합니다. Linux 저장소 작성자 잠금·시작 시 계수 재구성과 관리자 `vault usage` 조회를 추가했습니다. 신규 업로드가 막혀도 유효한 기존 객체의 조회와 동일 재전송은 유지합니다.
- **복구 보고서 v2:** `service-recovery verify`가 현재 계획·기대값·백업 해시, 필수 검사·관측 행 수·성공 상태, 보고서 나이·미래 시각을 대조합니다. 현재 백업이나 계획과 맞지 않는 과거 성공 기록을 거부합니다. 같은 바이트의 백업 경로 이동은 허용합니다.

## v0.3.0에서 업그레이드

1. 서비스를 중지하고 설정·DB·정책 상태·백업 및 별도 보관 저장소를 보관한 뒤 바이너리를 교체하세요. 서명 정책과 정상본 판정 형식은 유지됩니다.
2. 보관 서버의 기본 한도는 전체 100 GiB/1,000,000개, 에이전트별 10 GiB/100,000개, 최소 여유 1 GiB입니다. 기존 저장량과 `[capacity]`를 점검하세요. 시작 스캔 상한·불완전 객체·비정상 파일은 새 쓰기를 중단시킬 수 있습니다. 자동 삭제·수리는 수행하지 않습니다. [용량 설정](https://github.com/hkjang/ArgosAISecurity/blob/v0.4.0/docs/FEATURE_VAULT_CAPACITY.md)
3. 대기열은 선택 기능입니다. 전용 0700 디렉터리에 등록하고 필요한 주기로 `drain`을 호출하세요. 기본 1,000개 이력/256 MiB 대기 바이트 상한이 있으며 완료 이력도 항목 수에 포함됩니다. 증거 패키지 세 파일은 독립적으로 등록/전송되므로 모두 완료되었는지 확인하세요. 자동 예약·이력 정리는 제공하지 않습니다. [전송 대기열](https://github.com/hkjang/ArgosAISecurity/blob/v0.4.0/docs/FEATURE_VAULT_QUEUE.md)
4. 이전 v1 복구 보고서는 새 검증의 성공 근거로 사용할 수 없습니다. 현재 계획으로 `service-recovery test`를 다시 실행하고 `verify --max-age-secs N`으로 허용 나이를 명시하세요. 이 검사는 무서명 보고서의 일관성을 확인하며 작성자나 실행 출처를 인증하지 않습니다. [복구 보고서](https://github.com/hkjang/ArgosAISecurity/blob/v0.4.0/docs/FEATURE_SERVICE_RECOVERY.md)

## 검증

워크스페이스 **220개 테스트**와 별도 PostgreSQL 18.6 네이티브 복원 시험 **1개**가 통과했습니다. 큐의 DB 유실·초기화 중단 시 파일 보존, 통신 실패/재시도, 용량 제한, 보고서 변경·오래됨·읽는 중 변경을 회귀 검사했습니다. 최적화 바이너리에서 기존 스모크·보안 8개·보호/AI 5개·보관 4개·DB 복구 15개 및 신규 영속성 **7개 시나리오**가 통과했습니다. 실행 범위와 한계는 아래 검증 기록을 참고하세요.

## 다운로드와 확인

이전 릴리즈 형식대로 `argos-v0.4.0-linux-x86_64-gnu.tar.gz`와 `SHA256SUMS`를 제공합니다. `argos`, `argos-agent`, `argos-central`, `argos-vault` 네 실행 파일과 설정·문서·검증 스크립트·`BUILD_INFO.json`을 포함합니다. GNU/Linux x86_64, glibc 2.39 이상용입니다.

```bash
sha256sum -c SHA256SUMS
tar -xzf argos-v0.4.0-linux-x86_64-gnu.tar.gz
cd argos-v0.4.0-linux-x86_64-gnu
./bin/argos --version
python3 scripts/durability-scenarios.py --bin-dir "$PWD/bin"
python3 scripts/vault-scenarios.py --bin-dir "$PWD/bin"
python3 scripts/service-recovery-scenarios.py --bin-dir "$PWD/bin"
```

PostgreSQL 검증에는 별도 신뢰한 PostgreSQL 도구와 Linux bubblewrap이 필요합니다. 시험은 임시 데이터와 loopback 서버를 사용합니다. 설치 조건은 [바이너리 설치](https://github.com/hkjang/ArgosAISecurity/blob/v0.4.0/docs/INSTALL_BINARY.md), 실행 결과는 [검증 기록](https://github.com/hkjang/ArgosAISecurity/blob/v0.4.0/docs/PLATFORM_VALIDATION.md)을 참고하세요.

큐·수신증명은 저장 계층의 전원 차단 내구성이나 관리자 삭제 방지를 보증하지 않습니다. 논리 quota와 디스크 여유 확인은 물리 공간 예약이 아니며 외부 프로세스의 소비까지 통제하지 않습니다. 복구 보고서 검사는 전체 서비스 복구·검증된 RTO/RPO·신뢰 시각·출처 서명을 제공하지 않습니다.
